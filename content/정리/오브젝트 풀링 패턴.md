자주 생성/삭제되는 객체를 미리 만들어 재사용하는 패턴.

## 코드 예시

```csharp
GameObject bullet = pool.Get();
bullet.SetActive(true);
```

## 이해를 돕는 설명

반납할 때 위치, 체력, 이벤트 구독 같은 이전 상태를 초기화해야 한다. 풀 크기는 최대 동시 사용량을 기준으로 잡고 부족할 때 정책도 정한다.

## 더 깊이 이해하기

오브젝트 풀링 패턴 같은 설계 패턴은 특정 구현 모양을 외우는 것보다 어떤 변경과 결합 문제를 해결하는지 이해하는 것이 중요하다. 참여 객체의 책임, 의존 방향, 생성과 수명 관리, 테스트 가능성을 함께 살펴야 한다. 패턴을 적용한 구조가 단순한 직접 구현보다 복잡하다면 현재 문제에는 과도한 설계일 수 있다.

## 적용할 때 확인할 점

실제 적용 전에는 오브젝트 풀링 패턴 적용으로 줄어드는 결합도와 새로 생기는 클래스·간접 호출 비용을 비교한다. 인터페이스 경계와 소유권을 작게 유지하고 단위 테스트로 교체 가능성을 확인한다. 전역 상태나 숨은 의존성을 만드는 방식이라면 수명과 초기화 순서를 문서화한다.
