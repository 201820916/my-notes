- 코드 - 데이터 - 힙 - 스택

- 코드 : 작성한 소스 코드가 기계어로 변환되어 저장되는 영역 & READONLY

	- 크기는 컴파일 타임에 결정

	- C#에서는 GC가 자동으로 해제
	- 낮은 주소 -> 높은 주소 방향으로 자라며 계속 할당하면 메모리 누수 발생
	- 참조 타입

	- HEAP 메모리
	- 크기가 크거나 유동적인 데이터를 저장하기 위한 넓은 메모리 공간
	- 저장 데이터 : C#의 참조 타입 - class 객체, string, 배열 등
	- 동작 방식 : 개발자가 원할때(new 키워드 등) 필요한 만큼 동적 메모리 할당
	- 특징 : 메모리 크기 제한 X, 할당/해제 자동이지만 느림 

- 스택 영역 : 지역 변수, 매개 변수, 리턴 주소가 저장되는 영역
	- LIFO 방식 동작, 높은 주소 -> 낮은 주소 방향으로 자람
	- 함수 종료 시 해당 스택 프레임은 자동 해제
	- 값 타입
	
	- STACK 메모리
	- 임시 데이터들을 차곡차곡 쌓아두는 공간
	- 저장되는 데이터 : 매개변수, 지역변수, 값 타입 데이터
	- 동작 방석 : 후입선출(LIFO), 데이터 삽입(Push), 데이터 삭제(POP)
	- 특징 : 메모리 할당과 해제가 컴파일러에 의해 빠른 속도로 자동 수행됨, 크기 제한으로 큰 데이터는 불가능

## 박싱 / 언박싱

### 박싱
- 값 타입(스택에 저장)- > 참조 타입(힙에 저장)으로 변환하는 과정
- int, float, struct 등의 값을 object로 변환할 때 일어남
- 스택 메모리에 있던 값 타입 데이터가 힙 메모리 영역에 새롭게 할닫ㅇ
- 스택에는 힙 메모리를 가리키는 참조가 남음
- 특징 : 암시적 변환

```
int i = 123;
object o = i;
```

### 언박싱

- 반대로 참조타입(힙메모리) -> 다시 원래의 값 타입(스택메모리)로 되돌리는 과정
- 힙 영역에 저장된 객체에서 값을 꺼내옴
- 스택 영역의 값 타입 변수에 복사
- **정확히 일치하는 타입으로 명시적 캐스팅 필요**
-
```
object o = 123; // 박싱 
int j = (int) o; // 언박싱 (명시적 캐스팅 필수)
```


**MEMO**
- 딩연하지만 값형 - 값형 대입, 참조형 - 참조형 대입은 박싱/언박싱이 아님
- **태생부터 구분되는 자료형**을 인지하고 형 변환시 박싱-언박싱 발생

## 싱글턴

- 애플리케이션 전체에서 특정 클래스의 인스턴스를 단 하나만 생성하도록 보장
- 싱글턴 클래스의 세 가지 요소
	- private 생성자 - 외부에서 new로 인스턴스 생성을 막음
	- private static 인스턴스 필드 - 유일한 인스턴스를 저장
	- public static 프로퍼티 / 메서드 - 인스턴스 접근하는 단일 진입점

### 기본 구현

```
public class Singleton
{
    private static Singleton _instance;

    private Singleton() { } // 외부 생성 불가

    public static Singleton Instance
    {
        get
        {
            if (_instance == null) // ← 1. null인지 확인
                _instance = new Singleton(); // ← 2. null이면 새로 생성
            return _instance; // ← 3. 항상 인스턴스를 반환
        }
    }

    public void DoSomething()
    {
        Console.WriteLine("싱글턴 실행!");
    }
}

// 사용 예시
Singleton.Instance.DoSomething();
```

해당 코드는 \_instance 가 null인 경우에만 새 객체를 생성함

이미 존재하는 경우 기존 인스턴스를 반환함

## Const & Readonly

### const

- 상수화 
- 한번 설정된 값은 코드를 통해 값 변경이 불가능함.
- 선언과 동시에 값을 할당해야함.
```
const int gold = 100;

gold = 200; <- 불가능, 바꾸려면? const int gold = 200으로 직접 변경해야함.
```

### Readonly

- 상수화, 읽기 전용
- Const와의 차이점 : 선언 시점이나 생성자 내부에서만 값을 할당 할 수 있음.
- 필드가 아닌 지역 변수에서는 사용 불가

## 다형성

### 오버라이드

- 부모 클래스의 가상 메서드를 자식 클래스에서 새 구현으로 정의 하는 것
- 부모 메서드는 **virtual, abstract, override로 선언되어야 함**
- 자식 메서드는 **무조건 override** 키워드 필수
- **메서드 시그니처(이름, 파라미터 타입/순서, 반환 타입)가 동일**해야 함

```
class animal
{
	public virtual void Speak()
	{
		Console.WriteLine("동물이 소리를 낸다");
	}
}

class dog : animal
{
	public override void Speak()
	{
		Console.WriteLine("멍멍!");
	}
}

Animal a = new dog();

a.Speak(); // 멍멍이 출력됨.

```

#### override VS new

- 자식 메서드는 **무조건 override** 키워드 필수


**BUT new를 알아야 하는 이유가 있음**
- 컴파일러 경고 CS0108
```
class Parent
{
    public void Show() { Console.WriteLine("부모"); }  // virtual 없음
}

class Child : Parent
{
    // ⚠️ 경고: CS0108 — 'Child.Show' hides inherited member 'Parent.Show'
    //          Use the new keyword if hiding was intended
    public void Show() { Console.WriteLine("자식"); }
}
```

해결법
1. new 붙이기 - 의도적으로 숨김 명시
2. 이름 바꾸기

```
// 해결 방법 1: new 붙이기
public new void Show() { Console.WriteLine("자식"); }  // 경고 사라짐

// 해결 방법 2: 이름 바꾸기
public void ShowChild() { Console.WriteLine("자식"); }  // 경고 사라짐
```



| 상황                        | 키워드      | 이유              |
| ------------------------- | -------- | --------------- |
| 부모에 virtual<br>다형성 구현 목적  | override | 다형성 작동의 기본      |
| 부모에 virtual 없음            | new      | override 자체가 불가 |
| 부모 코드 수정 불가<br>(외부 라이브러리) | new      | 유일한 선택          |
| 이름이 겹침<br>BUT 의도는 아님      | 이름 바꾸기   | 가장 쉽고 깔끔함       |
| 의도적으로 부모 메서드 숨기기          | new      | 컴파일러에 의도 명시     |
| 아무것도 안함                   | 경고 발생    | 의도 불분명          |


### 오버라이드 & Base

Base 키워드
- 자식 클래스 안에서 부모 클래스의 멤버를 명시적으로 참조 하는 것.
- 부모 구현을 완전히 버리지 않고 그 위에 추가 로직만 얹을 때 사용
- 부모 생성자 호출
- 부모 속성/필드에 접근

```
class Person
{
    public string Name { get; set; }
    public int Age { get; set; }

    public Person(string name, int age)
    {
        Name = name;
        Age = age;
    }
}

class Player : Person
{
    public int Level { get; set; }

    // 부모 생성자에 값 전달 필수
    public Player(string name, int age, int level) : base(name, age)
    {
        Level = level;  // name, age 그대로 사용 및 자식 고유 level 파라미터 초기화
    }
}
```


### 오버로드

- 같은 클래스 내에서 **같은 이름의 메서드를 여러개** 정의 하는 것
- 컴파일러가 **호출 시점에 파라미터를 보고 어떤 메서드를 부를지** 결정
- **정적 바인딩(컴파일 타임 다형성)**

```
class Calc
{
    // 같은 이름 "Add"지만 파라미터가 완전히 달라서 OK
    public int    Add(int a, int b)      => a + b;      // ①
    public double Add(double a, double b) => a + b;     // ②
    public int    Add(int a, int b, int c) => a + b + c; // ③
}

var c = new Calc();
c.Add(1, 2);        // ① 호출
c.Add(1.5, 2.5);    // ② 호출
c.Add(1, 2, 3);     // ③ 호출
```

성립 조건

| 차이         | 가능여부 | 예시                                        |
| ---------- | ---- | ----------------------------------------- |
| 파라미터 개수 다름 | 가능   | Add(int, int) vs Add(int, int, int)       |
| 파라미터 타입 다름 | 가능   | Add(int, int) vs Add(double, double)      |
| 파라미터 순서 다름 | 가능   | Print(int, string) vs Print(string, int)  |
| 반환 타입만 다름  | 불가능  | int Add(int, int) vs double add(int, int) |

반환 타입이 다른 경우

```
// ❌ 컴파일 에러 
public int Do(int x) { return x; } 
public string Do(int x) { return x.ToString(); } /
/ 왜? 아래 호출 시 컴파일러가 고민: Do(5); 
// int를 기대하나? string을 기대하나?
```

## is & as

### is

타입 확인
- 객체가 특정타입과 호환되는지 확인하고 true/false 반환

```
object obj = "Hello";

obj is string;   // true
obj is int;      // false
obj is null;     // false (null이 아니므로)

null is string;  // false (null은 어떠한 타입도 아님)
```

선언 패턴
- 타입 확인 + 캐스팅 + 변수 선언
```
// 선언 패턴

object obj = "Hello";

if (obj is string s)
{
    Console.WriteLine(s.Length);  // 한 번 체크, 깔끔!
}

if (obj is not string) 
{ 
	// string이 아닐 때 실행 
}
```

### as

안전한 타입 캐스팅
- 참조 타입 또는 Nullable 타입 간의 안전한 형 변환을 수행
- 실패하면 exception대신 null 반환

```
object obj1 = "Hello";
object obj2 = 123;

string s1 = obj1 as string;   // "Hello" 성공
string s2 = obj2 as string;   // null (실패)

// null 체크 필수
if (s2 != null)
    Console.WriteLine(s2.Length);  // 실행 안 됨
```

## Static

- 인스턴스(객체) 없이 클래스 단위로 공유하는것
- **인스턴스 멤버는 객체마다 따로 있지만 static 멤버는 클래스 하나 당 한개만 존재**

### 중간 메모 : 인스턴스, static, 클래스

```
class Student // 클래스 명 Student
{
    public string name;       // 인스턴스 멤버 name, 각자 따로 가짐
    public static int count;  // static 멤버 count, 모두가 같이 씀
}

Student a = new Student();
Student b = new Student();

a.name = "철수";   // a의 것만 바뀜
b.name = "영희";   // b의 것만 바뀜

a.count = 1;       // count가 1이 됨
b.count = 2;       // count가 2로 바뀜

Console.WriteLine(a.count);  // 2  ← static은 모두가 같이 씀
Console.WriteLine(b.count);  // 2
```

## SerializeField

스크립트에서 변수를 선언

- public : 공개, 유니티 인스펙터 창에 노출되어 값을 수정 할 수 있음.
	- 다른 스크립트에서도 이 변수에 접근해서 값을 마음대로 바꿀 수 있음
- private : 다른 스크립트가 건드리지 못하게 숨김
	- 유니티 인스펙터 창에서도 사라져서 값 수정이 불가능

- **SerializeField : 변수의 성격은 Private & 유니티 수정 가능**
