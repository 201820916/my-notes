# 단어 정리

## C# / 프로그래밍 기초

### 언어와 실행 환경

#### 소프트웨어
기능과 디자인을 모아 놓은 프로그램적 구성물. 하드웨어 위에서 실행된다.

#### 하드웨어
소프트웨어를 실행하는 물리적 장치. CPU, 메모리, 저장장치 등이 포함된다.

#### 프로그램
특정 기능을 수행하기 위해 작성된 명령어의 모음.

#### 컴파일러 언어
사람이 읽기 쉬운 문법으로 작성한 코드를 컴퓨터가 실행 가능한 형태로 번역해서 사용하는 언어. C, C++, C#, Java 등이 있다.

#### 어셈블리어
기계어와 거의 1:1로 대응되는 저수준 언어. 하드웨어를 세밀하게 제어할 수 있지만 작성 난도가 높다.

#### 기계어
컴퓨터가 직접 이해하는 0과 1의 이진 코드. 실행은 빠르지만 사람이 읽거나 작성하기 어렵다.

#### 매니지드 언어
런타임 환경이 메모리 관리와 실행을 도와주는 언어. C#, Java, Python 등이 대표적이다.

#### 운영체제
사용자가 컴퓨터 자원을 쉽고 효율적으로 쓰도록 돕는 핵심 소프트웨어. 메모리, CPU, 파일, 프로세스 등을 관리한다.

#### 자원 분배
한정된 CPU, 메모리 같은 자원을 여러 작업에 효율적으로 나누어 주는 것.

#### 스케줄링
어떤 프로세스에 자원을 먼저 줄지 결정하는 운영체제의 관리 방식.

#### 닷넷 프레임워크
C# 프로그램 실행에 필요한 런타임과 라이브러리 환경. 코드 실행, 메모리 관리, 기본 기능을 제공한다.

#### namespace
이름 충돌을 막기 위해 코드를 이름 공간으로 묶는 C# 문법.

### 프로그램 구조

#### Main 함수
프로그램이 시작될 때 가장 먼저 실행되는 진입점.

#### 함수
특정 기능을 하나의 코드 블록으로 묶은 것. 반복 사용과 코드 분리에 유리하다.

#### 입출력
입력(Input)과 출력(Output)을 합친 말. 키보드 입력, 화면 출력, 파일 읽기 등이 포함된다.

#### 헤더 파일
C/C++에서 자주 쓰는 선언이나 기능을 모아 둔 파일. include로 가져와 사용한다.

#### 연산자
값 계산, 비교, 대입, 논리 판단 등을 수행하는 기호.

#### 제어문
코드 실행 흐름을 제어하는 문법. if, switch, for, while 등이 있다.

#### 조건문
조건이 참인지 거짓인지에 따라 다른 코드를 실행하는 문법.

#### switch문
하나의 값에 따라 여러 경우 중 하나를 선택해 실행하는 조건 선택문.

#### 반복문
특정 조건이 만족되는 동안 코드를 반복 실행하는 문법. for, while 등이 있다.

#### 삼항 연산자
조건 ? 참 : 거짓 형태로 if-else를 짧게 표현하는 연산자.

### 변수와 메모리

#### 변수
값을 저장하는 이름 붙은 공간. 자료형에 맞는 값을 담아 사용한다.

#### 지역 변수
함수나 블록 내부에서 선언되어 그 범위 안에서만 사용할 수 있는 변수.

#### 전역 변수
프로그램의 넓은 범위에서 접근 가능한 변수. 편하지만 남용하면 코드 관리가 어려워진다.

#### 상수
한 번 정해지면 값을 바꿀 수 없는 데이터. C#에서는 const나 readonly로 표현한다.

#### 자료형
데이터가 어떤 종류의 값인지 나타내는 분류. int, float, bool, string 등이 있다.

#### 값 타입
값 자체를 변수에 저장하는 타입. int, float, bool, struct 등이 대표적이다.

#### 참조 타입
실제 데이터의 주소를 변수에 저장하는 타입. class, string, array 등이 대표적이다.

#### 스택 메모리
지역 변수, 매개변수, 값 타입 데이터가 주로 저장되는 빠른 메모리 영역. 함수가 끝나면 자동으로 정리된다.

#### 힙 메모리
크기가 크거나 동적으로 생성되는 객체가 저장되는 메모리 영역. C#에서는 가비지 컬렉터가 관리한다.

#### 가비지 컬렉터
더 이상 사용되지 않는 힙 메모리 객체를 찾아 자동으로 회수하는 시스템.

#### 형 변환
데이터를 다른 자료형으로 바꾸는 작업. 값 손실 가능성을 주의해야 한다.

#### Unsigned
음수를 사용하지 않고 양수 범위를 더 넓게 쓰는 정수 타입 개념.

### C# 키워드와 타입

#### 박싱
값 타입 데이터를 object 같은 참조 타입으로 감싸 힙에 저장하는 과정.

#### 언박싱
박싱된 데이터를 원래 값 타입으로 다시 꺼내는 과정. 정확한 타입 캐스팅이 필요하다.

#### 제네릭
타입을 나중에 지정할 수 있게 만든 문법. 타입 안정성과 재사용성을 높인다.

#### Static
객체를 만들지 않고 클래스 단위로 공유되는 멤버. 모든 인스턴스가 같은 값을 공유한다.

#### System.Object
C#의 모든 타입이 기본적으로 상속받는 최상위 타입.

#### ToString()
객체를 문자열 형태로 표현할 때 사용하는 메서드.

#### const
선언과 동시에 값이 고정되는 컴파일 타임 상수.

#### readonly
선언 시점이나 생성자에서만 값을 정할 수 있는 읽기 전용 필드.

#### Enum
정수 값에 이름을 붙여 의미 있게 사용하는 사용자 정의 자료형.

#### ref
변수를 메서드에 참조로 전달해, 메서드 내부 변경이 호출한 쪽에도 반영되게 하는 키워드.

#### out
메서드가 여러 값을 반환할 때 사용하는 참조 전달 키워드. 메서드 안에서 반드시 값을 할당해야 한다.

#### is
객체가 특정 타입과 호환되는지 확인하는 키워드.

#### as
참조 타입을 안전하게 캐스팅하는 키워드. 실패하면 예외 대신 null을 반환한다.

### 객체지향

#### 인터페이스
클래스가 반드시 구현해야 하는 기능 목록을 정해두는 약속. 서로 다른 클래스를 같은 방식으로 다루게 해준다.

#### 프로퍼티
필드 값을 안전하게 읽고 쓰기 위한 C# 문법. get/set으로 접근을 제어한다.

#### 클래스
데이터와 기능을 묶어 객체를 만들기 위한 설계도.

#### 인스턴스
클래스를 바탕으로 실제 메모리에 생성된 객체.

#### 캡슐화
데이터와 기능을 하나로 묶고 외부 접근을 제한해 안전하게 관리하는 객체지향 원칙.

#### 구조체
값 타입으로 동작하는 사용자 정의 자료형. 작은 데이터 묶음에 적합하다.

#### 다형성
같은 형태의 호출이 객체에 따라 다르게 동작하는 객체지향 성질.

#### 오버라이드
부모 클래스의 가상 메서드를 자식 클래스에서 새롭게 구현하는 것.

#### 오버로드
같은 이름의 메서드를 매개변수 차이로 여러 개 정의하는 것.

#### base
자식 클래스에서 부모 클래스의 멤버나 생성자를 명시적으로 참조하는 키워드.

#### this
현재 객체 자신을 가리키는 키워드.

### 의존성과 이벤트

#### 의존성
한 코드가 다른 클래스나 객체에 기대어 동작하는 관계.

#### 강한 의존성
특정 클래스를 직접 생성하거나 강하게 참조해 수정과 교체가 어려운 상태.

#### 의존성 주입(DI)
필요한 객체를 내부에서 만들지 않고 외부에서 전달받는 방식. 결합도를 낮춘다.

#### 델리게이트
메서드를 변수처럼 담고 전달할 수 있게 하는 타입.

#### 이벤트
델리게이트 기반으로 특정 일이 발생했음을 외부에 알리는 구조.

#### 콜백
특정 작업이 끝났거나 특정 시점이 되었을 때 다시 호출되는 함수.

#### 튜플
여러 값을 하나로 묶어 간단히 반환하거나 전달할 때 쓰는 자료형.

#### 확장 메서드
기존 클래스 코드를 수정하지 않고 메서드를 추가한 것처럼 사용할 수 있는 문법.

#### 람다
이름 없는 함수를 짧게 표현하는 문법. 콜백이나 LINQ에서 자주 사용한다.

## 문자열 / 데이터 처리

### 문자열 처리

#### 문자열 포함 검사
문자열 안에 특정 문자가 들어있는지 확인하는 기능. C#에서는 Contains()를 사용한다.

#### 문자열 보간
문자열 안에 변수 값을 직접 끼워 넣는 문법. C#에서는 `$""` 형태를 사용한다.

#### ToLower()
문자열을 소문자로 바꾸는 메서드.

#### ToUpper()
문자열을 대문자로 바꾸는 메서드.

#### Split()
문자열을 특정 기호나 문자를 기준으로 나누는 메서드.

#### Format()
지정한 자리표시자에 값을 넣어 문자열을 만드는 기능.

### 자료구조와 알고리즘

#### 알고리즘
문제를 해결하기 위한 절차나 규칙의 모음.

#### 자료구조
데이터를 효율적으로 저장, 검색, 추가, 삭제하기 위한 구조.

#### 선형 자료구조
데이터가 일렬로 연결된 구조. 배열, 리스트, 스택, 큐 등이 있다.

#### 비선형 자료구조
데이터가 계층이나 망 형태로 연결된 구조. 트리, 그래프, 힙 등이 있다.

#### 배열
같은 타입의 데이터를 연속된 공간에 저장하는 자료구조.

#### 연결 리스트
각 데이터가 다음 데이터의 위치를 가리키며 연결되는 자료구조.

#### 스택
마지막에 들어온 데이터가 먼저 나가는 LIFO 자료구조.

#### 큐
먼저 들어온 데이터가 먼저 나가는 FIFO 자료구조.

#### 트리
부모와 자식 관계로 이루어진 계층형 자료구조.

#### 그래프
정점과 간선으로 관계를 표현하는 비선형 자료구조.

#### Big-O 표기법
입력 크기가 커질 때 알고리즘의 시간이나 메모리 사용량이 얼마나 증가하는지 표현하는 방식.

#### 시간복잡도
입력 크기에 따라 실행 시간이 얼마나 늘어나는지 나타내는 개념.

### 외부 데이터

#### 데이터 드리븐
코드에 직접 값을 넣지 않고 외부 데이터로 동작을 제어하는 방식.

#### 테이블
게임 데이터나 설정값을 행과 열 형태로 정리한 자료.

#### 데이터 모델
외부 데이터를 코드에서 사용하기 위해 만든 class 또는 struct 구조.

#### JSON
데이터를 key-value 형태로 저장하는 가벼운 텍스트 포맷.

#### XML
태그 구조로 데이터를 표현하는 텍스트 포맷.

#### 직렬화
객체나 데이터를 파일, 문자열, 네트워크 전송이 가능한 형태로 바꾸는 과정.

#### 역직렬화
저장된 문자열이나 파일 데이터를 다시 코드 객체로 복원하는 과정.

#### 인스턴스 데이터
게임 실행 중 생성되거나 변하는 실제 플레이 상태 데이터.

## 유니티

### 엔진과 빌드

#### 유니티
게임과 실시간 콘텐츠를 제작하는 게임 엔진. C# 스크립트와 컴포넌트 구조를 사용한다.

#### Mono
C# 코드를 중간 언어로 변환한 뒤 실행 중 기계에 맞게 번역하는 JIT 기반 빌드 방식.

#### IL2CPP
C# 코드를 중간 언어와 C++을 거쳐 기계어로 변환하는 AOT 기반 빌드 방식.

### 오브젝트 구조

#### 컴포넌트
GameObject에 붙여 기능을 추가하는 부품 단위.

#### GameObject
유니티 씬에 존재하는 기본 객체 단위. 실제 기능은 컴포넌트를 붙여 구성한다.

#### MonoBehaviour
유니티 스크립트가 컴포넌트로 동작하게 해주는 기본 클래스.

#### 라이프 사이클
Awake, Start, Update처럼 MonoBehaviour가 실행되는 순서와 흐름.

#### 브로드캐스팅
메시지를 여러 대상에게 퍼뜨려 전달하는 방식.

#### 프레임
게임 화면이 한 번 갱신되는 단위.

#### SerializeField
변수는 private로 유지하면서 유니티 인스펙터에서 값을 수정할 수 있게 하는 속성.

### 프리팹과 에셋

#### 프리팹
미리 만들어 저장해 둔 GameObject 템플릿.

#### 언팩 프리팹
프리팹 연결을 끊고 현재 씬의 일반 오브젝트로 바꾸는 작업.

#### Instantiate
프리팹이나 오브젝트를 런타임에 새로 생성하는 함수.

#### Destroy
런타임에 오브젝트나 컴포넌트를 제거하는 함수.

#### Asset
유니티 프로젝트에서 사용하는 리소스 파일.

#### Asset Reimport
에셋을 다시 불러와 유니티가 최신 상태로 인식하게 하는 작업.

#### Package
유니티 기능이나 외부 라이브러리를 묶어 배포하는 단위.

#### Package Manager
유니티 패키지를 설치, 삭제, 업데이트하는 관리 도구.

#### Addressable
리소스를 주소 기반으로 관리하고 필요할 때 로드하는 유니티 시스템.

#### Game Manager
게임 흐름, 상태, 공통 시스템을 관리하는 중심 관리자 객체.

#### 리소스 관리
필요한 에셋을 적절한 시점에 로드하고 사용 후 해제하는 작업.

### 좌표와 시간

#### 좌표계
오브젝트의 위치와 방향을 표현하는 기준 체계.

#### Vector2
x, y 두 축으로 이루어진 2D 벡터.

#### Vector3
x, y, z 세 축으로 이루어진 3D 벡터.

#### Quaternion
3D 회전을 표현하는 자료형. 오일러 각보다 회전 꼬임 문제가 적다.

#### 오일러 각
x, y, z 축의 각도로 회전을 표현하는 방식.

#### Time.deltaTime
이전 프레임부터 현재 프레임까지 걸린 시간.

#### TimeScale
게임 시간의 흐름 속도를 조절하는 값.

#### Transform
오브젝트의 위치, 회전, 크기를 담당하는 컴포넌트.

#### SetParent
Transform의 부모를 변경하는 함수.

#### Translate
Transform을 기준 방향으로 이동시키는 함수.

#### LookAt
오브젝트가 특정 대상을 바라보도록 회전시키는 함수.

#### Rotate
오브젝트를 지정한 각도만큼 회전시키는 함수.

### 물리와 충돌

#### Rigidbody
물리 엔진의 영향을 받게 하는 컴포넌트.

#### AddForce
Rigidbody에 힘을 가해 움직이게 하는 함수.

#### Collider
충돌 영역을 정의하는 컴포넌트.

#### Trigger
물리적으로 막지는 않고 겹침 여부만 감지하는 충돌 설정.

#### Raycast
한 방향으로 보이지 않는 광선을 쏴서 충돌 대상을 검사하는 기능.

#### Overlap
특정 영역 안에 들어온 Collider들을 검사하는 방식.

#### AABB 충돌
축에 정렬된 박스 기준 충돌 판정. 계산이 빠르다.

#### OBB 충돌
물체의 회전까지 반영한 박스 충돌 판정. 더 정확하지만 비용이 크다.

### UI와 2D

#### 레이아웃
화면 안의 UI 요소를 배치하는 구조.

#### UI 뎁스
UI가 화면에 그려지는 앞뒤 순서.

#### 레터박스
화면 비율 유지를 위해 남는 공간에 여백을 넣는 방식.

#### 나인 슬라이스
이미지를 9개 영역으로 나눠 모서리 품질을 유지한 채 크기를 늘리는 UI 기법.

#### Atlas
여러 이미지를 하나의 큰 텍스쳐로 묶은 것.

#### UGUI
유니티의 기본 UI 시스템.

#### 2D Sprite
2D 게임에서 사용하는 이미지 객체.

#### Sprite Renderer
Sprite를 씬에 표시하는 컴포넌트.

#### TileMap
타일 이미지를 격자에 배치해 맵을 만드는 유니티 2D 기능.

#### RigidBody2D
2D 물리 엔진의 영향을 받게 하는 컴포넌트.

#### Collider2D
2D 충돌 영역을 정의하는 컴포넌트.

#### 애니메이션
시간에 따라 오브젝트의 상태를 변화시키는 기능.

### 비동기 처리

#### 비동기
작업이 끝날 때까지 프로그램 전체를 멈추지 않고 진행하는 처리 방식.

#### IEnumerator
C#에서 순차적으로 값을 반환하거나 유니티 코루틴을 구성할 때 사용하는 인터페이스.

#### 코루틴
여러 프레임에 걸쳐 작업을 나누어 실행하는 유니티 기능.

#### UniTask
유니티에서 async/await를 효율적으로 쓰기 위한 비동기 라이브러리.

## 디자인 패턴

### 패턴 개요

#### 디자인 패턴
자주 발생하는 설계 문제에 대한 검증된 해결 방식.

### 생성 패턴

#### 싱글턴 패턴
애플리케이션 전체에서 특정 클래스의 인스턴스를 하나만 만들도록 보장하는 패턴.

#### 팩토리 패턴
객체 생성을 별도 클래스나 메서드에 맡기는 생성 패턴.

#### 제네릭 팩토리
제네릭을 이용해 여러 타입의 객체 생성을 공통 방식으로 처리하는 팩토리 구조.

### 구조 패턴

#### 플라이웨이트 패턴
많은 객체가 공유 가능한 데이터를 함께 사용하게 해 메모리 사용을 줄이는 구조 패턴.

#### 파사드 패턴
복잡한 내부 시스템을 단순한 인터페이스 하나로 감싸는 구조 패턴.

#### 어댑터 패턴
서로 맞지 않는 인터페이스를 중간에서 변환해 함께 사용할 수 있게 만드는 구조 패턴.

#### 데코레이터 패턴
기존 객체를 감싸 기능을 동적으로 추가하는 구조 패턴.

### 행동 패턴

#### 옵저버 패턴
한 객체의 변화가 여러 구독자에게 자동으로 전달되는 행동 패턴.

#### 상태 패턴(FSM)
객체의 상태에 따라 행동을 분리하는 패턴.

#### 커맨드 패턴
요청을 객체로 캡슐화하는 패턴.

#### 전략 패턴
알고리즘이나 행동 방식을 객체로 분리해 교체 가능하게 만드는 패턴.

#### 중재자 패턴
객체들이 서로 직접 참조하지 않고 중재자를 통해 소통하게 하는 패턴.

### 게임 최적화 패턴

#### 오브젝트 풀링 패턴
자주 생성/삭제되는 객체를 미리 만들어 재사용하는 패턴.

#### 비헤이비어 트리
AI 행동을 트리 구조로 구성하는 패턴.

## 3D / 렌더링

### 3D 화면 표현

#### 투영
3D 공간의 물체를 2D 화면에 표현하는 과정.

#### 원근 투영
멀리 있는 물체가 작게 보이도록 표현하는 투영 방식.

#### 직교 투영
거리에 따른 크기 변화 없이 표현하는 투영 방식.

#### 소실점
평행한 선들이 멀리서 한 점으로 모이는 것처럼 보이는 지점.

#### 빌보드
카메라를 향해 항상 정면을 보도록 회전하는 오브젝트.

### 하드웨어와 화면 단위

#### CPU
복잡한 연산과 게임 로직 처리를 담당하는 중앙 처리 장치.

#### GPU
대량의 그래픽 연산을 병렬로 처리하는 장치.

#### 픽셀
화면을 구성하는 가장 작은 점 단위.

### 메쉬 구성

#### Vertex
3D 모델의 점. 위치, 색상, UV, 노멀 같은 정보를 담을 수 있다.

#### Edge
두 정점을 연결한 선.

#### Polygon
여러 정점과 선으로 이루어진 면.

### 렌더링 과정

#### 드로우 콜
CPU가 GPU에게 오브젝트를 그리라고 요청하는 호출.

#### 렌더링 파이프라인
3D 데이터가 화면의 픽셀로 바뀌기까지 거치는 전체 처리 과정.

#### 로컬 스페이스
오브젝트 자기 자신을 기준으로 한 좌표 공간.

#### 뷰 스페이스
카메라를 기준으로 변환된 좌표 공간.

#### 컬링
화면에 보이지 않거나 필요 없는 오브젝트를 렌더링 대상에서 제외하는 최적화 과정.

#### 라이팅
빛과 표면 정보를 계산해 밝기와 색을 결정하는 단계.

#### 클리핑
카메라 범위 밖의 부분을 잘라내는 처리.

#### 래스터라이즈
3D 도형을 화면의 픽셀 단위로 변환하는 과정.

#### 포스트 프로세스
렌더링이 끝난 화면에 추가 효과를 적용하는 단계.

### 렌더링 최적화

#### 라이트맵
조명 결과를 미리 텍스쳐로 구워 저장한 것.

#### Sprite Atlas
여러 스프라이트를 하나로 묶어 렌더링 효율을 높이는 텍스쳐 묶음.

## 머테리얼 / 텍스쳐

### 재질 구성

#### 머테리얼
3D 오브젝트가 시각적으로 어떤 재질처럼 보일지 결정하는 에셋.

#### 셰이더

#### 쉐이더 그래프

#### 컷아웃

## 네비게이션 / AI

### 길찾기

#### NavMesh
AI가 걸어 다닐 수 있는 영역을 단순화된 메쉬로 표현한 길찾기 데이터.

#### 웨이포인트
AI가 따라갈 지점을 미리 배치해 경로를 만드는 방식.

#### 커스텀 패스 메쉬
AI 이동을 위해 별도로 만든 단순화된 경로용 메쉬.

#### 네비메쉬 베이킹
씬의 지형과 장애물을 분석해 AI가 이동 가능한 NavMesh 데이터를 미리 생성하는 과정.

#### NavMeshSurface
특정 범위나 오브젝트를 기준으로 NavMesh를 생성하는 유니티 컴포넌트.

#### NavMeshAgent
NavMesh 위에서 목적지까지 경로를 찾아 이동하는 AI 이동 컴포넌트.

#### NavMeshObstacle
움직이는 장애물이나 문처럼 길을 막는 대상을 AI가 피하도록 만드는 컴포넌트.

#### Carve
NavMeshObstacle이 네비메쉬에 실시간으로 구멍을 내 경로를 막게 하는 옵션.

#### NavMeshLink
끊어진 NavMesh 구역 사이를 연결하는 링크.

### AI 구조

#### 행동트리
AI 행동을 조건과 행동 노드의 트리로 구성하는 방식.

#### FSM
유한 상태 머신. 정해진 상태와 상태 전환으로 객체 행동을 관리하는 구조.

### 행동트리 노드

#### Composite 노드
여러 자식 노드를 가지고 실행 순서나 규칙을 제어하는 행동트리 노드.

#### Selector 노드
자식 노드 중 하나라도 성공하면 성공을 반환하는 행동트리 노드.

#### Sequence 노드
모든 자식 노드가 성공해야 성공을 반환하는 행동트리 노드.

#### Decorator 노드
하나의 자식 노드를 감싸 조건을 붙이거나 결과를 바꾸는 행동트리 노드.

#### Leaf 노드
자식이 없는 행동트리의 말단 노드.

#### Action 노드
AI가 실제로 이동, 공격, 애니메이션 재생 같은 행동을 수행하는 노드.

#### Condition 노드
AI 상태나 주변 조건을 검사해 성공/실패를 반환하는 노드.

#### Inverter
자식 노드의 성공과 실패 결과를 반대로 바꾸는 데코레이터 노드.

#### Repeater
자식 노드를 특정 횟수나 조건만큼 반복 실행하는 데코레이터 노드.

#### Parallel 노드
여러 자식 작업을 동시에 실행하는 행동트리 노드.
