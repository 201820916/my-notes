데이터를 key-value 형태로 저장하는 가벼운 텍스트 포맷.

## 코드 예시

```json
{
  "name": "Player",
  "level": 3
}
```

## 이해를 돕는 설명

사람이 읽기 쉽고 웹과 설정 파일에서 널리 쓰이지만 주석과 타입 정보가 제한적이다. 대용량 이진 데이터나 성능이 중요한 저장에는 다른 포맷이 적합할 수 있다.

## 더 깊이 이해하기

JSON 관련 작업에서는 에디터의 원본 데이터, 빌드 결과물, 런타임에 로드된 인스턴스를 구분해야 한다. GUID와 참조 관계, 임포트 또는 직렬화 규칙, 로드·해제 시점, 플랫폼별 설정이 서로 연결된다. 데이터 구조나 배포 방식이 바뀔 수 있다면 버전 호환성과 누락 시 처리도 설계한다.

## 적용할 때 확인할 점

JSON 관련 데이터는 소유자와 해제 책임을 명확히 하고, 에디터에서는 정상이어도 빌드에서 누락될 가능성을 확인한다. 플랫폼별 압축과 경로, 대소문자, 비동기 실패, 데이터 버전 변경을 테스트하며 원본 .meta 파일과 GUID를 버전 관리에서 함께 보존한다.
