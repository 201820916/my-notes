태그 구조로 데이터를 표현하는 텍스트 포맷.

## 코드 예시

```xml
<player>
  <name>Player</name>
  <level>3</level>
</player>
```

## 이해를 돕는 설명

속성과 중첩 구조, 스키마를 표현하기 좋지만 JSON보다 문법이 길다. 시작 태그와 종료 태그가 맞아야 하며 특수문자는 이스케이프해야 한다.

## 더 깊이 이해하기

XML 관련 작업에서는 에디터의 원본 데이터, 빌드 결과물, 런타임에 로드된 인스턴스를 구분해야 한다. GUID와 참조 관계, 임포트 또는 직렬화 규칙, 로드·해제 시점, 플랫폼별 설정이 서로 연결된다. 데이터 구조나 배포 방식이 바뀔 수 있다면 버전 호환성과 누락 시 처리도 설계한다.

## 적용할 때 확인할 점

XML 관련 데이터는 소유자와 해제 책임을 명확히 하고, 에디터에서는 정상이어도 빌드에서 누락될 가능성을 확인한다. 플랫폼별 압축과 경로, 대소문자, 비동기 실패, 데이터 버전 변경을 테스트하며 원본 .meta 파일과 GUID를 버전 관리에서 함께 보존한다.
