## 튜플


- 튜플은 여러개의 데이터를 하나로 묶어서 사용할때 쓰는 보관함
- 클래스를 만들기 번거로워 잠깐 묶을때는 좋음 

```
// 클래스 없이 간단히 묶기
(string name, int age, float score) player = ("너구리", 6, 98.5f);
Console.WriteLine(player.name);  // 너구리

// 메서드 반환값으로 활용
(int min, int max) GetRange(int[] arr) => (arr.Min(), arr.Max());

var (min, max) = GetRange(new[] { 3, 1, 4, 1, 5 });
Console.WriteLine($"min: {min}, max: {max}");
// min : 1 , max : 5
```

## 확장메서드

- 클래스 내에 메서드가 정의/상속되지 않아도 해당 클래스가 원래 있었던 메서드처럼
- 새로운 기능을 추가할 수 있게 해주는 정적(Static)메서드

```
// 반드시 static 클래스 안에 static 메서드로 정의
// 첫 번째 파라미터에 'this 대상타입' 붙이기
public static class StringExtensions
{
    public static bool IsNullOrEmpty(this string str) 
        => string.IsNullOrEmpty(str);

    public static string Repeat(this string str, int count)
        => string.Concat(Enumerable.Repeat(str, count));
}

// 사용 — string 원래 메서드처럼 호출 가능
string s = "Ha";
Console.WriteLine(s.Repeat(3));      // HaHaHa
Console.WriteLine("".IsNullOrEmpty()); // True
```
## 싱글턴

- 특정 클래스의 인스턴스를 오직 1개만 생성하고
- 어디서든 그 인스턴스에 접근 할 수 있도록 보장하는 패턴
-  Instance라는 **정적 프로퍼티**를 통해 접근

- 의존성이 1개로 몰리는 것은 사실
- 게임 개발에서는 매니저 클래스가 없을 수 가 없음
	- 남용 X -> 대표적 역할 정도만 하도록 조정
	- 매니저의 종류는 한정됨.
- 관리를 편하게 하기 위한 중앙 처리 시설

```
public class GameManager
{
    // 유일한 인스턴스를 정적 프로퍼티로 제공
    private static GameManager _instance;
    public static GameManager Instance
    {
        get
        {
            if (_instance == null)
                _instance = new GameManager();
            return _instance;
        }
    }

    private GameManager() { }  // 외부 생성 차단

    public int Score { get; private set; }
    public void AddScore(int value) => Score += value;
}

// 어디서든 동일한 인스턴스에 접근
GameManager.Instance.AddScore(100);
Console.WriteLine(GameManager.Instance.Score); // 100
```

## 익명 함수와 람다

- 람다 : 익명 함수를 만들기 위한 문법
	- 이름없는 함수를 즉석에서 정의하고 변수처럼 전달(콜백 파라미터) 하거나 실행
	- 단점 - 디버깅 난해, 재사용X, 코드가독성 하락, 메모리 관리 어려움

- 람다 주의점
	- 람다는 정적 영역에 저장되어 사용됨
	- 람다 밖에 있는 변수를 내부에서 사용할때 이슈 발생
	- 람다 안에서 객체 생성시에도 GC 발생
	- 네트워크 콜백 같은 상황이 아니면 과연 정말 람다가 필요한가? -> 고심

```
// 델리게이트 변수에 람다 저장
Func<int, int, int> add = (a, b) => a + b;
Console.WriteLine(add(3, 5)); // 8

// 콜백 파라미터로 전달
void ProcessItems(List<int> items, Action<int> callback)
{
    foreach (var item in items)
        callback(item);
}

ProcessItems(new List<int> { 1, 2, 3 }, x => Console.WriteLine(x * 2));

// ⚠️ 클로저 주의 — 외부 변수 캡처시 GC 이슈 가능
int multiplier = 3;
Func<int, int> multiply = x => x * multiplier; // multiplier 캡처됨
```
## 제네릭 T

- 데이터 형식을 미리 정하지 않고 **사용할 때 결정**하는 방식
- 제네릭 클래스 \<T\> : 어떤 형식이던지 들어올 수 있음
- 제네릭 T는 where : 인터페이스
- where : 부모클래스로 T가 될 수 있는 클래스의 범주를 제한 할 수 있음
- 장점 : 제네릭 내부 로직에서 인터페이스나 부모 클래스의 프로퍼티(또는 멤버변수), 메서드 호출 가능

```
public interface IDamageable
{
    void TakeDamage(int amount);
    int Hp { get; }
}

public class Monster : IDamageable
{
    public int Hp { get; private set; } = 100;
    public void TakeDamage(int amount) => Hp -= amount;
}

// where로 T의 범주 제한 → 내부에서 인터페이스 멤버 호출 가능
public class BattleSystem<T> where T : IDamageable
{
    private T _target;
    public BattleSystem(T target) => _target = target;

    public void Attack(int damage)
    {
        _target.TakeDamage(damage);
        Console.WriteLine($"남은 HP: {_target.Hp}");
    }
}

// 제네릭 메서드
public static T FindFirst<T>(List<T> list, Func<T, bool> predicate)
    where T : class
    => list.FirstOrDefault(predicate);

// 사용
var system = new BattleSystem<Monster>(new Monster());
system.Attack(30); // 남은 HP: 70

var monsters = new List<Monster> { new Monster(), new Monster() };
var found = FindFirst(monsters, m => m.Hp == 100);
```
