
## 컴포넌트

- 유니티에서 컴포넌트란 **MonoBehaviour를 상속받는 클래스**
- MonoBehaviour 상속 X -> 순수 C# 클래스
- MonoBehaviour는 타고타고 올라가면 Component를 상속 받음.
- C#의 기능들이 잘 호환됨

## MonoBehaviour의 라이프 사이클


생성단계

| 생성<br>(creation) | ->  | 초기화<br>(Initialization) | ->  | 활성화<br>(Enabling) | ->  | 시작<br>(Starting) |
| ---------------- | --- | ----------------------- | --- | ----------------- | --- | ---------------- |
|                  |     | Awake()                 |     | OnEnable()        |     | Start()          |

반복단계

| FixedUpdate() | ->                             | Update() | ->  | LateUpdate() |
| ------------- | ------------------------------ | -------- | --- | ------------ |
|               | OnTriggerXXX                   |          |     |              |
|               | OnColisionXXX                  |          |     |              |
|               | **물리연산이 필요한**<br>**프레임에서 불려짐** |          |     |              |


### MonoBehaviour와 메세지 시스템

### 브로드캐스팅

Update, Start, OnEnable 등을 실행하는 방식

- 메세지 기반의 특징
	- 발신자 - 수신자 전원 신경쓰지 않음(**독립성 유지**)
	- 메세지 기반 -> 여러 객체가 동시에 OnEnable이 되더라도 **순서는 보장되지 않음**


## Update()문과 상속 주의 사항

부모 클래스가 Update문이 있는 경우
- Update를 오버라이드 해서 정의하지 않아도 호출이 가능함


### 프레임

- Frame(FPS, Frames Per Second)
	- 1초 동안 스크린에 보여지는 정지 이미지의 수를 나타냄.
	- 24 Frame -> 주료 영화에 사용
	- 60 Frame Over -> 스포츠, 게임 등 생동감 있고 매끄러운 화면을 제공
- Frame in Unity
	- 화면 갱신되는 **최소 단위의 정지 이미지**
	- Update()문 -> 프레임마다 1번 실행(즉, 1초 120fps는 120번 호출)
	- 프레임 독립성을 위해 Time.deltaTime를 곱해주어 기기의 프레임 속도와 상관없이
	  **오브젝트가 초당 일정한 일정한 속도로 이동하도록 만들어야 함.**
- Fixed Update
	- 일관된 물리법칙이 필요한 경우 FixedUpdate()를 이용함
	- 설정된 고정 시간(기본 0.02초)에만 반응
	- 물리적 세상은 무조건 0.02초마다 한번씩 계산된다는 규칙을 보장

## Game Object

- 씬에 존재하는 모든 객체와 컴포넌트를 담는 그릇
	- 여기에 MeshRenderer가 있으면 시각적으로 보임
	- Rigidbody를 넣으면 물리 연산이 적용됨
- 모든 게임 오브젝트는 반드시 Transform을 가짐
- 유니티에서는 **어떤 컴포넌트가 필요한가**로 접근


## 프리팹

- 미리 만들어진 설계도, 템플릿
- 씬에서 동일한 설정의 오브젝트를 복제하고 생성 -> 한꺼번에 수정할 수 있게 해줌
	- 프리팹은 실시간 데이터로 원본과 링크되어 있음
- 오버라이드 개념도 제공

### 언팩 프리팹

- 원본과의 링크 해제 -> 독립적인 게임 오브젝트화
- 프리팹의 대규모 수정 OR 새로운 프리팹을 만들어야 할 때 종종 사용

### Instantiate

- 프리팹을 게임 세상에 실체화
- 메모리안의 프리팹 데이터 복사 -> 하이어라키 뷰에 오브젝트 생성
- 이는 메모리 할당하는 무거운 작업
### Destory

- 게임 오브젝트를 씬에서 제거
- 메모리 해제
- **호출 즉시 삭제 X**
	- 현재 프레임의 모든 로직이 끝난 후 정리 시간에 삭제
	- 즉시 삭제 -> DestoryImmediate 

## Assets

- Assets 폴더 안에 담긴 모든 파일
	- 게임을 제작하는데 필요한 모든 외부 자원
		- Sound
		- Particle
		- 2D/3D Model
		- Texture
		- Audio
		- Prefabs
		- Materials
		- etc...


### Asset Reimport

- 원본 리소스를 유니티 엔진이 읽을 수 있는 내부 데이터로 **재변환**
- 파일 변경 -> 유니티에 반영이 안됨? -> Reimport


## Package

- 아트 에셋, 플러그인, 스크립트를 하나로 압축
- 특정 기능이나 에셋을 하나로 묶어 여러 프로젝트에서 쉽게 재사용 + 공유

- Unity Registry Packages : 유니티 공식 제공 패키지
- Asset Store Package : 에셋 스토어에서 다운로드 된 패키지
- Custom Package : 개발자가 직접 만든 패키지

### Package manager

- 패키지 매니저를 통해 다운 받은 패키지는 **글로벌 캐시의 패키지를 참조해 사용**
	- 실제 다운로드 X -> 패키지 주소, 버전 등 정보만 프로젝트에 저장
