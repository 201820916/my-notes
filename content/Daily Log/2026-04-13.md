
## 프로퍼티

- **변수의 가독성**과 **메서드**의 안정성을 하나로 합친 개념
- 객체 내에 존재, **멤버변수의 데이터 부 역할을 하는 기능인 메서드 활용**

- **멤버 변수는 숨기는 게 좋음 ( 캡슐화 )
* 필요한 기능은 Public 메서드로 구현
* **필요한 데이터만 읽고 쓸 수 있게** 

```
public Item Bag { get; set; }
```


### 프로퍼티 발전 과정

- 1단계 : Public으로 멤버 변수를 사용 -> 변수 직접 노출 -> 캡슐화 없음

- 2단계 : private 멤버 변수 + Get() Set() 함수를 멤버 변수 별로 만들기
	- 안전하지만 코드의 복잡도 증가
	
- 3단계 : Getter / Setter 프로퍼티
	- 게임 개발에서는 이용하는 경우 꽤 많음
	
- 4단계 : 위와 원리는 동일하나 더 심플한 get; set;



## 의존성

- 내가 어떤 일을 하기 위해 다른 클래스의 도움이 꼭 필요한 경우
- 또는 내 내부의 데이터나 기능이 어떤 클래스를 참조하는 경우
### 강한 의존성의 문제점


확장성
- 문제상황 : 기획자가 플레이어의 무기를 “검”이 아니라 “마법봉”으로 바꿔달라고하면
- Sword 클래스가 아니라 Wand로 바꿔야함 (문제는 이런 변경이 한두번이 아닐 것)


유지보수성
- 문제상황 : 플레이어가 체력 로직 수정 시 이 플레이어를 참조하는 UI 체력바, 전투 AI, 플레이어 랭킹 등 여러 class에서 동시에 영향을 줄 수 있음

재 사용성
- 바나나 하나를 원했는데, 바나나를 들고 있는 고릴라와, 그 정글 전체를 얻게 된다 (조 암스트롱)

협업
- 같은 파일을 수정하게 되는 경우가 많아짐 (충돌 및 머지 문제 발생)
- 테스트 주도 개발 불가 (플레이어와 관련된 조건뿐만 아니라, 다른 로직들이 연결되어 테스트 환경구성이 까다로워짐)


### 왜 위험한가?

- 강한 의존성은 한 곳의 변경이 다른 클래스에 영향을 크게 미침.
- 수정 비용의 기하급수적으로 늘어남.


## 의존성을 푸는 방법


### 문제 상황
`
```
public class Sword
{
    public void Attack() => Console.WriteLine("검으로 공격!");
}

public class Player
{
    private Sword _weapon = new Sword(); // ① Player가 직접 Sword를 생성

    public void Attack() => _weapon.Attack();
}
```

- 해당 코드는 new Sword()가 내부에서 직접 생성됨
- 만약 Sword가 Wand로 교체될때 player 코드는? -> 직접 수정해야함


### 의존성 주입(DI)


```
public class Sword
{
    public void Attack() => Console.WriteLine("검으로 공격!");
}

public class Wand
{
    public void Attack() => Console.WriteLine("마법봉으로 공격!");
}

public class Player
{
    private Sword _weapon;

    public Player(Sword weapon) // ② 생성자로 외부에서 주입
    {
        _weapon = weapon;
    }

    public void Attack() => _weapon.Attack();
}

// 사용
Player player = new Player(new Sword()); // ③ 외부에서 결정
```


### 의존성 주입(인터페이스)

```

public interface IWeapon // ④ 무기의 공통 규격(계약)을 정의
{
    void Attack();
}

public class Sword : IWeapon
{
    public void Attack() => Console.WriteLine("검으로 공격!");
}

public class Wand : IWeapon
{
    public void Attack() => Console.WriteLine("마법봉으로 공격!");
}

public class Player
{
    private IWeapon _weapon; // ⑤ 구체 클래스가 아닌 인터페이스에 의존

    public Player(IWeapon weapon) // ⑥ 인터페이스 타입으로 주입
    {
        _weapon = weapon;
    }

    public void Attack() => _weapon.Attack();
}

// 사용
Player playerA = new Player(new Sword()); // 검 사용 플레이어
Player playerB = new Player(new Wand());  // 마법봉 사용 플레이어

```
