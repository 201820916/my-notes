
# 서버

- **Serv**ant = 하인
- **Serv**e = 제공하다
- **Serv**ice = 어떤 것을 제공하다

**Serv** = 어떤 대상에게 뭔가 제공하고 관리를 하는 맥락

- 즉, Server는 클라이언트에게 요청을 받고 그 요청에 해당되는 검증된 데이터/결과를 제공하는 프로그램

- 로컬이든 원격이든 두 프로그램 간의 정보 송수신이 가능
	- 한쪽이 여러 클라이언트의 요구를 수행하고 일관된 서비스를 제공

- CS는 컴퓨터 사이언스라는 단어도 있지만 클라이언트-서버 구조를 지칭할때도 사용

## 서버가 터졌다?

- 서버가 터졌다 = 서버에 접속 할 수 없다
	- 물리적 : 서버 프로그램을 구동하는 PC가 꺼짐(정전, 재부팅)
	- 소프트웨어적 1 : 해당 서버 프로그램이 실행중이지 않다.(크래시, 메모리 부족)
	- 소프트웨어적 2 : 서버 PC 포트로 프로그램에 접근 할 수 없다.(포트포워딩, 방화벽)
	- 물리적 : 내 IP로 해당 PC와 송수신 불가능(IP 차단)

## 요즘은?

- 하드웨어 발전
	- 메모리나 CPU 성능의 비약적 발전
		- 대량의 유저가 접속해도 메모리 부족이나 CPU 병목으로 터지지 않음

- 클라우드 기반 서버 운영
	- 이전에는 물리적 수용 가능한 동시접속자를 고려해서 서버 PC 물리적 구비
	- 고려를 넘어선 수요에 맞춘 물리적 서버 즉시 증축이 어려움
	- 클라우드 서버는 비용이 더 많이 들지만 서버 스케일 조절이 쉬움

- 언어와 아키텍쳐 발전
	- C++ 기반 서버에서 올바르지 않은 메모리 공간에 참조를 시도 & 논리적 에러
		- 서버 프로그램이 종료
	- 현재는 C# Null 체크를 통한 메모리 안정성 확보 및 구조 설
		- C++ 포인터 관리 기법 다양화
		- 에러 발생 시에도 Catch 문만 벗어나는 식으로 프로그램 안정적 운용 가능

## 통신 방법

- 소켓 통신
- 연결을 하기 위한 준비 과정 존재
	- 연결 이후 종료 명령까지 연결이 유지되는 통신 방법
	- TCP/IP UDP


- HTTP 통신
	- 유튜브, 구글, 페이스북 등 웹페이지에 접속 할때 데이터를 받아오는 통신 방식
	- HTTP 통신 혹은 웹통신으로 많이 불려옴.
	- **물어볼 때만 잠깐 연결하고 응답이 끝나면 연결을 끊어버림**


- 예시
	- MMORPG : 마을에 접속하면 원하지 않아도 다른 플레이어들이 움직이는 것을 볼 수 있음
	- 유튜브 페이지 : 해당 페이지가 새로고침을 하지 않으면 다시 할때까지 내용이 고정되어 있음

### HTTP 통신에서 받아오는 정보

- 웹페이지의 레이아웃 정보, 내용, 이미지
	- HTML CSS JS

- ==Git 에서 풀을 받으면== 추가된 내용이 ==유니티 에디터에서 확인==할 수 있음
- ==웹페이지를 새로고침 하면== 서버에 저장된 이미지나 레이아웃 정보를 받아와서 ==화면에 출력==

- 브라우저 캐시
	- 이 과정에서 같은 이미지를 다시 다운받지 않도록 브라우저 캐시에 저장
	- 이미지가 바뀌지 않거나 웹 페이지 정보가 이상할 때 주기적으로 캐시나 기록을 지움

- 쿠키
	- 유저 정보나 유저가 설정한 임시 정보 저장
		- Ex) 일주일 동안 이벤트 페이지 그만 보기


### 웹 게임은 왜 많이 없는가?

- 브라우저 캐시를 주기적으로 삭제
	- 그렇다면 웹게임은 페이지를 새로고침 할때마다 리소스를 매번 새롭게 받아야 함
	- 무거운 웹게임은 존재하기 힘들고 넷플릭스&유튜브도 오프라인 저장 기능을 권장

### 웹 게임이 아닌 게임 내 웹 통신

- 게임 프로그램을 미리 다운로드 & 통신으로 최소한의 정보는 웹 통신으로 수신 
	- 소켓 통신보다 비용의 차이가 압도적을 적음
	- 방치형 게임 & 클라이언트 위주 랭킹 게임 & 카지노 & 퍼즐류에서 주로 사용

- 게임 내 새로 고침 기능이 없는데?
	- 사용자가 직접 누르거나 사용자에게 노출이 되어있지 않음
	- 내부적으로 새로고침 & 웹 통신 요청-응답이 담겨져 있음
