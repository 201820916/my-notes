
## 유니티에서의 객체간 정보 전달


- GameObject로 받아오기
	- 장점 : ObjectA나 ObjectC를 등록할 수 있다
	- 대신 GetComponent를 통해서 사용하려는 컴포넌트를 빼서 써야한다.

- GameObejct의 컴포넌트로 받아오기 **(타입이 확실하다면)**
	- 바로 프로퍼티나 기능을 사용할 수 있다.


- ID 기반 전달 ( 동적 생성 )
	- 게임 오브젝트 보관
	- 객체 찾기 및 기능 호출


### 동적 생성 게임 오브젝트와 관련된 매니저 종류

1. 상호작용 객체 관리
	- MosterManager
	- EnemyManager
	- ObjectManager
	- EntityManager
		- 플레이어 다음으로 중요한 상호작용 객체들을 관리하는 매니저
		- 몬스터-Enemy를 따로 두거나 ObjectManager안에서 나누는 경우도 있음
		- NPCManager - 퀘스트 관련(전투 관련X)여서 따로 두기도 함

2. 시청각 및 스킬 요소 관리
	- VFXObjectManager
	- SoundManager
	- SkillObejctManager
	- 이펙트, 사운드, 스킬(+투사체) 관련된 게임 오브젝트들을 관리

3. 필드 객체 관리
	- FieldObejctManager
		- 드랍된 아이템
		- 채집물
		- 퀘스트용 객체
		- 워프 포인트 등등

4. 배경 및 구역 스케줄링 관리
	- MapObjectManager
	- ChunkManager
	- SectorManager
	- StaticObjectManager
	- AreaObjectManager
		- 플레이어 이동에 따라 움직이지 않는 배경요소들을 구역별로 로드/언로드 스케줄링

5. UI 관리
   - UIManager

### 게임 오브젝트와는 관련 없지만 순수 C# 클래스 또는 시스템적으로 필요

1. 씬 및 공간 관리
	- WorldManager / SceneManager / ZoneManager
		- 장면이나 플레이어의 장소를 관리

2. 입력 및 네트워크 관리
	- InputManager
		- 입력 시스템 중앙화
	- NetworkManager
		- 서버와 데이터를 주고받는 패킷 및 동기화 관련 로직 담당.

3. 데이터 및 리소스 관리
	- DataManager
	    - 게임에서 사용되는 (기본) 데이터를 로드하고, 필요한 데이터를 제공. 
	    
	- SaveManager
	    - DataManager가 기본 데이터를 다룸
	    - SaveManager는 인스턴스(플레이하면서 쌓이는) 데이터를 저장.
	        
	- ResourceManager
	    - 게임의 리소스를 로드하는 매니저. 
	    - (어드레서블 시스템 선호 / 메모리 해제와 번들 다운로드 스케줄링)

4. 기타 시스템 관리
	- TimeManager
	    - 서버 표준 시간으로 각종 날짜 관련 정보 초기화를 수행합니다.
	    - 일시 정지 상태와 재진행을 관리합니다. (단순 타임 스케일 조작이 아님)
	        
	- QuestManager
	    - 퀘스트 조건 여부를 체크합니다.
	    - 예: 퀘스트의 유형별로 구독을 열어두고, 특정 행동 달성 시 이 매니저에서 체크
	    - 퀘스트의 진행도를 보관. (세이브 매니저와 데이터를 주고받기도 함)
