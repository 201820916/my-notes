

# 3D

## 투영 (Projection)

- 차원이 높은 공간에 가상으로 존재하는 객체들을 차원이 낮은 공간으로 변환하는 과정
	- 3D 세계 -> 2D 한장으로 그려내는 과정

## 원근 투영 - Perspective

- 인간의 눈이나 실제 카메라 렌즈가 세상을 바라보는 방식과 가장 유사한 투영방식
- 멀리 있는 물체 - 작게 / 가까이 있는 물체 - 크게
- **소실점** 존재, 화면의 깊이감과 입체감이 왜곡 없이 표현

### 소실점 Vanishing Point

- 화면상에서 한점에 모여 마침내 사라지는 지점
- 소실점 개수 -> 1점 투시, 2점 투시, 3점 투시 등 다양한 원근 연출이 가능
- 우리 모니터로 보고 있는 3D는 과연 진짜 3D 세계인 것인가?
	- 특정 소실점을 기준으로 표현한 수학적 약속의 결과물?

### 직교 투영 Orthographic

- 물체와 카메라 사이 거리에 상관 없이 물체의 실제 크기를 그대로 화면에 투영
- 거리감 무시, 멀리있는 물체와 가까이 있는 물체의 크기가 **완전히 동일**
- 2D와 UI에서 자주 사용되는 투영법 -> **원근이 필요 없는 작업**

### 빌보드 Billboard

- 배경 -> 원근 투영 / 플레이어, 캐릭터 -> 카메라를 바라보게 하는 경우
- 카메라가 움직일 때 마다 "빌보드" 게임 오브젝트는 카메라를 바라보도록 지속적 회전
- 3D 게임 속 HUD, 3D 오브젝트를 따라다니는 이름과 텍스트를 표현할때
	- Plane이나 TextMesh에 이 기법을 사용하기도 함




## CPU & GPU

CPU
- 중앙처리장치
- 컴퓨터 메인 컨트롤러
- OS 구동, 프로그램 실행, 내부 모든 하드웨어 제어
- **직렬처리**
	- **한번에 하나의 직업을 아주 깊고 빠르게**


GPU
- 그래픽 처리 장치
	- 단순한 사칙연산을 푸는 1000명의 사람들
- GPU는 화면에 그래픽을 그려주기 위해 태어난 특수목적 장치
- **모니터 화면의 수백만 개 픽셀을 동시 계산**
- **병렬 처리와 수많은 데이터를 한꺼번에 쏟아부어 처리하는 능력 우수**





## PIXEL


화면을 크게 확대하면 매끄러운 그림이 아닌 수많은 작은 네모칸들의 집합체임

- 작은 네모칸 = 1픽셀
- **각 픽셀은 단 한가지 색상만 가질 수 있음**
	- 픽셀 내부에 3개의 작은 픽셀이 존재하며 각각 RGB를 표시
	- 이 수백만개의 색상 점들이 모여 영화, 게임, 사진, 같은 거대한 이미지 완성
	- FHD(1920\*1080) = 가로 픽셀 1920개
	- 4K UHD(3840\*2160) = 가로 픽셀 3840개




## 점(Vertex), 선(Edge), 면(Polygon)

### 점
- 모든 3D 형태의 시작점
- 기하학적의 위치를 결정하는 최소 단위
- 크기가 없고, 위치와 속성 정보를 갖춤

### 선
- 모델의 외곽선이나 와이어프레임 구조를 형성
- 선 자체로는 두께가 없음

### 면
- 세개 이상의 버텍스가 닫힌 형태로 연결되어 만들어지는 평면
- 게임에서 보는 물체의 표면
- 색, 텍스쳐 투입 -> 렌더링
- 삼각형과 사각형으로 사용용도에 따라 구분해서 면을 표현
	- 삼각형 : GPU 연산할때 가장 기본적이고 안정적인 단위
	- 사각형 : 디자이너가 3D 모델을 다룰 때 사용

#### 사각형 이상의 다각형이 없는 이유
- GPU의 의도하지 않는 면 분할
	- 억지로 대각선을 긋거나 등 ->  3D 모델의 변형
	- 애니메이션 삽입 시 찢어짐

## 드로우 콜

렌더링 준비 단계(CPU)
- GPU가 파이프라인을 돌리기 전
	- CPU는 메인 메모리에서 데이터를 정리하고 가공 하는 작업 선 진행
	- 게임 로직 처리, 물리 연산, 캐릭터 이동 계산, 카메라 시야에 어떤것이 보이는지(컬링)
	- 그려야 할 오브젝트들의 정점 정보, 텍스쳐, 셰이더 데이터를 그래픽 카드 메모리 전송

드로우 콜 단계
- CPU가 모든 준비를 마친 후 
- 그래픽 API(DirectX, Vulkan 등)을 통해 GPU의 명령 큐에 명령어를 던짐
- VRAM 몇번 주소의 데이터로 화면에 드로잉 명령
- 이 요청 자체를 드로우 콜 또는 디스패치라고 부름 (이 명령까지 CPU 주도)

렌더링 파이프라인 단계(GPU) : 
CPU의 요청을 받은 GPU는 이제 렌더링 파이프라인을 가동
- 대표적으로 정점 셰이더 작업 : 3D 공간의 점들을 화면 좌표로 변환
- 래스터화 (Rasterization) : 3D 도형을 모니터에 보여줄 픽셀 덩어리로
쪼갬
- 픽셀, 프레그먼트 셰이더 (Pixel Shader) : 쪼개진 픽셀 하나하나의 최종
색상을 계산
- 출력 병합 (Output Merger) : 최종 화면을 버퍼에 기록하고 모니터로 출력



## 렌더링 파이프라인

- 3D 가상 공간의 정점, 텍스쳐, 라이팅 등의 수치 데이터를 우리가 “모니터(2D)”로 볼 수 있는 2D 픽셀 이미지로 변환하는 “공정”

### 렌더링 파이프라인 - 로컬 스페이스

GPU 사용
- 모든 3D 모델이 처음 생성되었을 때의 0,0,0을 기준으로 메쉬를 그림
- 로컬 스페이스를 기준으로 형태를 먼저 형성함

### 렌더링 파이프라인 - 뷰 스페이스

GPU (정점 셰이더)
- 카메라를 세계 중심으로 두고 카메라가 바라보는 방향을 기준으로 모든 정점 좌표 재정렬
- 뷰 변환 행렬이 곱해짐

### 렌더링 파이프라인 - 컬링 화면 추려내기

CPU + GPU
- CPU 단계 : 드로우 콜을 주기 전 카메라 시야에 통째로 안보이는 덩어리 오브젝트 폐기
- GPU 단계(백페이스 컬링) : 카메라를 등지고 있는 삼각형의 뒷면을 연산에서 제거

### 렌더링 파이프라인 - 라이팅

GPU (정점 셰이더 or 픽셀 셰이더)
- 정점 파이프라인(고전), 픽셀 파이프라인(현대)
- 빛을 계산하는 단계
- 정점 라이팅 : 이 타이밍에 정점 셰이더가 정점 단위로 빛을 계산 
	- (연산은 빠르지만 부드럽지 못함)
- 픽셀 라이팅(Phong) : 정점의 법선 데이터만 잘 보존했다가 나중에 **픽셀 셰이더에서 픽셀단위로 정교하게 빛 계산**

- 정점 셰이더 -> 래스터라이즈 -> 픽셀 셰이더 순으로 전환

### 렌더링 파이프라인 - 클리핑

GPU (하드웨어)
- 카메라 시야 경계선에 걸친 삼각형들을 칼로 자르듯 잘라냄
	- 잘린 경계면에 새로운 정점을 생성
- 화면 밖에 완전히 벗어난 정점은 완전히 제거. 
	- (이 연산을 정밀하게 하기 위해 내부적으로 투영 연산의 도움을 받음)


### 렌더링 파이프라인 - 투영

GPU (정점 셰이더)
- 원근감을 주는 원근 투영이나, 직교 투영(Orthographic) 행렬을 곱함
- 이 단계를 거치면 3D 공간이 시야 볼륨(Frustum) 안의 표준화된 입방체 공간(NDC: $-1$에서 $1$ 사이의 공간)으로 압축됨


### 렌더링 파이프라인 - 뷰포트 변환

GPU (하드웨어)
- 가상의 수학적 정육면체 좌표(-1 ~ 1)를 플레이어가 사용하는 실제 모니터 해상도(예: 1920 x 1080 픽셀 좌표) 크기로 매핑하여 강제로 찌그러뜨려 맞추는 단계
- 이로써 정점들의 모든 공간 여행이 끝남

###  렌더링 파이프라인 - 래스터라이즈

GPU 고정 기능 장치 (하드웨어)
- 정점 파이프라인 -> 픽셀 파이프라인으로 전환되는 교차로
- 설명: 지금까지 수학적 선과 점(정점)으로만 이루어져 있던 3D 삼각형들을 모니터에 뿌릴 수 있는 '픽셀(Pixel) 세포 덩어리'로 쪼개는 단계
- 이 래스터라이즈가 끝나야만 비로소 다음 단계인 '픽셀 셰이더'가 작업을 이어받아 화면에 색칠공부(텍스처, 최종 라이팅)를 시작할 수 있음
#### 레스터?

독일어 인쇄 용어: Raster (격자 / 스크린)
- 인쇄 기술자들은 신문에 사진을 인쇄하기 위해 이미지를 아주 미세한 점들로 쪼개는 그물망 같은 판을 사용함

### 래스터라이즈 이후

- 래스터라이즈가 끝나면, 이 정점 데이터는 보간되어 픽셀 위치에 맞게 쪼개져서 들어오고 그 이후에 다음과 같은 작업 진행
- 픽셀셰이더는 이제 실제 눈에 보여질 “색상”을 계산
- 텍스쳐 샘플링 -> UV좌표를 이용해 알베도(Albedo), 노멀(Normal), 러프니스(Roughness) 등 텍스쳐에서 색상과 제어값을 읽어옴
- 라이팅 계산 -> 픽셀 위치의 노멀 벡터와 라이트 방향, 뷰 카메라 방향을 계산해 디퓨즈, 스페큘러 등의 음영 계산
- 최종 색상 -> 모든 연산 후 픽셀 셰이더는 최종 색상값 (RGBA) 반환


### 포스트 프로세스

- 픽셀 셰이더 연산 이후 추가 보정
	- 안티 앨리어싱 : 계단 현상 제거
	- 앰비언트 오클루전 : 부피감 향상을 위한 음영처리
	- 뎁스 오브 필드 : 대형 센서 카메라 사용한 것 같은 영화 느낌
	- 모션 블러 : 액션감 있는 화면에서 프레임 전환을 자연스럽게 -> 어지러움 유발
	- 블룸 : 조명 번짐 정도를 더 강하게(빛의 강도가 아닌 번짐 강도 UP)
