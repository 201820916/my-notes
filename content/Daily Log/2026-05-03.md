
## UI와 데이터 드리븐

- UI에 텍스트나 이미지를 바꿀때 인스펙터에서 하나씩 수정 & 하드코딩 불가능
- 데이터 드리븐은 외부에서 이를 가능케 하고 수정도 용이함
- 씬에 미리 매니저를 넣어주고 Awake에서 받아오는 방법 존재


## Game Manager

- 전반적인 상태( 점수, 진행도, 게임 오버 상태 등 )을 관리하는 중앙 통제소의 역할
- 인스턴스 데이터를 가지고 있다가 적정 시점에 저장도 수행
	- 세이브 로드 매니저도 가능하지만 볼륨이 작다면 게임 매니저 이용 가능

## 리소스 관리

- Resource.Load
	- 프리팹, 이미지, 3D모델 등등 게임에서 다양한 리소스를 동적으로 로드하고 사용



### Adressable

- 종속성 지옥
	- 에셋 번들 : A번들 캐릭터가 B번들 텍스처를 쓸때
		- B번들을 먼저 로드해야하며 실수하면 텍스처가 깨진 핑크색으로 나옴
	- 어드레서블 : 알아서 사용해야할 텍스처와 쉐이더 등을 추적하여 로드

- 메모리 관리
	- 에셋 번들 : Unload(true)와 Unload(false)의 차이를 완벽히 이해해야함
		- 참조카운팅을 직접 구현하지 않으면 메모리 누수와 크래시가 빈번히 발생
	- 어드레서블 : 레퍼런스 카운팅 내장, 호출 1번으로 메모리 안전한 해제

- 경로 및 이름 관리
	- 에셋 번들 : 경로와 이름을 코드로 정확히 입력해야 로드 할 수 있음
	- 어드레서블 : 설정한 주소 문자열 하나로 로드

- 빌드 및 테스트
	- 에셋 번들 : 수정사항 확인을 위한 매번 번들 빌드
	- 어드레서블 : 패스트 모드 등을 통한 에셋 로딩 즉시 테스트


## 비동기

- 스레드
	- 유니티는 싱글 스레드 기반, 대부분의 로직을 밴드시 메인 스레드에서만 수행
	- 워커 스레드
		- 메인 스레드 외 백그라운드에서 복잡한 계산을 대신 해주는 보조 스레드
		- Unity의 C# Job System을 사용해 안전하고 효율적 활용 가능
	- 다만, 먼저 싱글 스레드 비동기를 잘 이용하도록 연습하는것을 추천

- 비동기
	- 결과가 나올때까지 기다리지 않고 다음 일을 하겠다
	- 스레드는 이 방식을 구현할 수단
	
	- 멀티 스레드 기반 비동기
		- 어떤 작업을 별도의 워커 스레드에 던지고 메인 스레드는 계속 게임 작업 수행
			- 어드레서드 파일 로딩
			
	- 싱글 스레드 기반
		- 코루틴
			- 스레드 새로 생성X, 메인 스레드 안에서 이번 프레임에 할만큼만 하고
			- 다음 프레임으로 작업을 미룸
			- 동시에 일하는 것은 아님 BUT 사용자 입장에선 멈춤이 적어 비동기 처럼 보임


- 장점
	- 자원활용 극대화
	- 사용자 경험 향상
	- 높은 처리량

- 단점
	- 설계 및 구현 복잡성
	- 디버깅 어려움
	- 데이터 일관성
