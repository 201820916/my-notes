
# 월드매니징

- 하나의 게임 월드를 지속, 플레이어에게 일관된 규칙을 제공
- 월드 총괄인 최상위 관리자가 공통으로 반드시 보관하고 처리해야하는 정보+기능 존재

- 글로벌 상태와 환경 정보
	- 월드 타임 -> 낮밤, 인게임 시간 etc...
	- 글로벌 시즌과 날씨 상태
	- 인게임 글로벌 이벤트

- 플레이어 세션 관리
	- 글로벌 유저 정보 : 현재 월드에 접속한 모든 플레이어의 고유 ID, 캐릭터 이름, 계정상태
	- 마이그레이션 : 유저가 다른 공간으로 넘어갈때 데이터 안전한 이동
		- 워프 포탈 -> 이동한 맵에 대한 정보를 가져와 맵 로드 + 플레이어 순간이동

- 데이터 동기화
	- 플레이어에게 보여줘야 하는 지역의 데이터를 데이터 매니저를 통해 수신 및 관리

# 월드 - 심리스

- 로딩 없음, 끊김없는 탐험
- 현대 오픈월드 게임필수 사용
- 원리
	- 눈에 보이는 곳 / 곧 갈 곳을 실시간으로 메모리에 올리고 내림
	- 레벨 스트리밍 OR 월드 파티션 : 맵을 격자로 쪼개서 관리
	- LOD : 절대 도달 못하는 원경 = 로우 폴리곤
	- 밉맵 : 텍스쳐 또한 동일하게 가까이 있으면 고해상도, 멀리 있으면 저해상도
- 심리스 레벨 디자인
	- 청크(월드 조각 단위)가 단절 없이 이어져야함
	- 클라이언트 : 리소스의 절차적 로딩
	- 서버 : 같은 공간분할 데이터로 관리

## 레벨 스트리밍

눈에 보이는 곳과 곧 갈곳을 실시간으로 메모리에 올리고 내리는 기술
- 레벨 스트리밍 또는 월드 파티션 : 맵을 격자로 쪼개서 관리 ( 위치 실시간 추적 )
- 거름망 전략 알고리즘
	- 연산이 더 작은 비용으로 가장 상위 카테고리 문제를 해결하고 하위 카테고리로 넘어오는 접근법
		- 전체 맵의 격자 형태를 판정 하는 비용은 적음
		- 플레이어 위치가 특정 격자에 들어오면 그 주변 격자의 리소스를 비동기로 로드
		- 멀어진 타일은 언로드


## LOD - Level of Detail

- 멀리 있는 지형이나 에셋은 하이폴리곤 메쉬 대신 로우 폴리곤 메쉬로 대체
	- 렌더링 부하 낮춤
- 동일한 지형&건물도 여러 단계의 메쉬 리소스 준비
	- 다운로드 용량 증가 BUT 실시간 최적화 타협

## 밉맵

- 텍스쳐 최적화
	- 가까운 이미지 -> 원본 해상도
	- 먼 이미지 -> 저해상도
- 이 기능을 이용하려면 텍스쳐가 2의 거듭제곡이여야 함
- 밉맵은 원래 텍스쳐의 크기를 절반씩 줄여가며 미리 작은 이미지를 만들어 두는 기술
- 2의 거듭제곱이 아니면 밉맵 생성이 불가능하거나 왜곡
- 그래서 일반적인 게임 리소스의 텍스쳐가 512, 1024, 2048


### 심리스 서버 클라 기술 접근 차이


| 클라이언트                                 | 서버                                                     |
| ------------------------------------- | ------------------------------------------------------ |
| 화려하게 보여주기                             | 부딫히고 이동하기                                              |
| 고해상도 메쉬, 텍스쳐, 밉맵, LOD                 | 내비메쉬(몬스터가 이동할 수 있는 경로 데이터)                             |
| 이펙트, 풀/나무, 라이팅 데이터                    | 콜라이더                                                   |
| 플레이어 주변 수 백 미터 이내 시각 자원               | 시각적 정보는 제거                                             |
| 플레이어 위치 기준으로 시각적 리소스를 <br>동적 로드 / 언로드 | 플레이어 및 몬스터 이동 연산을 위해<br>해당 구역의 충돌 / 이동 지형 데이터만 메모리에 유지 |
데디케이티드 서버 관련 플러그인으로 심리스 서버를 구현한다면 이런 정보들이 관리됨

- 단, 이 데이터조차 불필요한 정보들이 껴있는경우가 있어서, 대형 게임사에서는 직접 구현한
클래스로 최소한의 정보 송수신으로 심리스 서버를 구현하려고 함

- ex. 네비메쉬를 그대로 사용하는 것이 아니라 네비메쉬와 관련된 구조체와 클래스를 직접
최소한의 정보와 알고리즘만을 이용해 구현 (ex.DaniTechNavMeshData)


# 존 & 룸

## 존 방식

- 세계가 여러개의 거대한 구역(Zone)으로 나뉘어 있는 방식
- 구역과 구역 사이를 이동할 때 로딩 화면이 등장
- 대표적으로 MMORPG

장점
- 개발 및 설계 용이성
	- 각 존의 독립으로 인해 레벨 디자이너들이 구역별로 독립적 작업하기 편함
	- 최적화 역시 해당 존 내부 리소스만 신경쓰면 됨. 기준 명확.
- 안정적 성능
	- 로딩 화면에서 필요한 자원을 100% 다 올린 후 게임이 시작
		- 플레이 도중 맵 로딩으로 인한 프레임 드랍이 적음

단점
- 몰입감 저해 : 빈번한 로딩은 유저의 텐션을 떨어뜨림
- 경계의 단절 : 물리적-시각적 연속성이 사라짐

## 룸 방식

- 맵을 매우 작은 방 또는 스테이지 형태로 관리
- 로그라이크, 탑다운, 클래식 RPG
- 절차적 맵 생성과 잘 맞는 방식

- 장점
	- 극대화된 최적화 : 방 하나만 연산하면 되므로 사양이 낮아도 고성능 내기 쉬움
	- 오브젝트 컬링의 직관적
	- 높은 리플레이 가치 : 방들을 조합하는 방식 -> 새 맵의 절차적 생성 구현 유리

- 단점
	- 스케일의 한계 : 거대하고 웅장한 대자연이나 오픈월드의 감성을 전달하기 불가능
	- 반복감 : 조합이 다양하지 않으면 금방 지루함을 느낌

### 모둘형 룸 에셋(프리팹)

- 문 위치가 구격화된 다양한 방들을 프리팹으로 미리 구현
- 그래프 기반 알고리즘 배치
	- 게임 시작되거나 던전에 진입할때 방들이 무작위로 연결 -> 하나의 던전 레이아웃 생성
- 룸 단위 활성 / 비활성
	- 유저가 문을 통과해 다음 방에 진입하면 이전방의 몬스터나 연산을 완전히 끌 수 있음
