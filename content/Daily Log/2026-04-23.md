## Quaternion과 오일러

오일러 각
- X, Y, Z 세개의 축을 기준으로 한 회전 각도 시스템
- 문제점 발생
	- X, Y, Z축을 **순서대로 회전**(회전 누적)하다보니 직관적이지만, **짐벌 락** 문제가 발생함.
	- 짐벌 락 : 회전을 하다보니 축이 합쳐져서 회전을 못하는 경우
- Quaternion
	- 회전을 4개 성분으로 표현
	- 시작점과 도착점을 잇는 새로운 가상의 축 임시 생성
		- 그 축을 중심으로 한번에 회전
	- 회전 합성, 보간, 내부계산에서 오일러 각보다 더 안정적이고 효율적

In Unity
- 표현은 오일러 각으로 표현 -> 입력과 이해에 유리
- 내부 계산은 쿼터니언으로 저장하고 처리함. -> 계산과 안정성에서 유리


## Time.deltaTime

```
private void Update()
{
	_timer += Time.deltaTime;
	if (_timer >= 3.0f)
	{
		Debug.Log("3초가 지났습니다!");
		_timer = 0f;
	}
}
```

- Time.deltaTime이란 **이전 프레임에서 현재 프레임까지 걸린 시간**
- **게임의 로직을 프레임 단위가 아니라, 시간 단위로 처리하기 위해 반드시 이해해야 함**
- **프레임이 높을수록 deltaTime은 작아지고, 프레임이 낮을수록 deltaTime은 커짐**
- 시간 체크의 경우 float 연산이기 때문에 == 연산자가 아니라 <=, >=, >, < 같은 연산자를 사용

## TimeScale

- Time.timeScale은 시간의 흐름을 **배율로 관리**할 수 있게 해줌
- 타임 스케일이 0이 되면, **Update()는 멈추지 않고, FixedUpdate는 멈춰서 호출되지 않음**
- 물리 법칙에서의 시간은 제어할 수 있으나, **유니티 엔진 자체를 멈추는 것은 아님**
- 느려지는 연출이 필요하다면, 타임 스케일보다는 연출 영역에서의 제어

## RigidBody

- 유니티의 Transform
	- 벽 통과, 중력 무시
- Rigidbody 컴포넌트 -> 질량을 가진 **물리적** 객체화
	- Use Gravity : 중력 부여
	- Drag : 마찰&저항
	- Collider와 결합 : 충돌 반응
	- Is Kinematic : 물리 지배를 일시적 무시 -> 일시적으로 코드를 통한 처리 필요
	- Interpolate : 프레임 간 이동을 부드럽게 보간
	- Constraint : 위치&회전 고정 필요시 사용

#### LinerVelocity & AddForce

| 구분    | LinerVelocity<br>(  속도 대입  ) | AddForce<br>( 힘 전달 )     |
| ----- | ---------------------------- | ------------------------ |
| 비유    | 순간 이동급 가속                    | 천천히 속도가 올라감              |
| 제어력   | 매우 높음<br>(정해진 속도로 움직임)       | 낮음<br>(질량&저항 변수)         |
| 느낌    | 딱딱하고 정확함<br>(플랫폼 게임, 퍼즐)     | 부드럽고 묵직함<br>(레이싱, 시뮬레이션) |
| 주요 용도 | 캐릭터 걷기, 점프, 컨트롤 등            | 미사일, 차량, 폭발 등            |

## 충돌

### AABB 충돌

- Axis Aligned Bounding Box
- 정렬된 축을 이용한 충돌 체크
- 매쉬의 방향과 충돌 박스의 축이 일치하지 않을 수 있음.
- In Unity : **절대 충돌할 일 없는 오브젝트들을 걸러내는 1차 검사 용도**
	- Collider.bounds가 대표적 AABB
	- 연산이 매우 가볍고 빠름

### OBB 충돌

- Oriented Bounding Box
- Bounding Box를 이용한 충돌 체크 알고리즘
- 박스에 +축이 더해진다.

- 회전과 일치하기 때문에 1차에서 **충돌 가능성이 있는 오브젝트들을 좀 더 정밀하게 계산**
- AABB보다 연산량 많음
	- BoxCollider가 대표적 OBB


## Collider

- 물리적 형체를 정의한느 컴포넌트
- 무언가와 부딫히거나 충돌을 감지할 수 있게 해줌
	- 충돌, 트리거, 레이캐스팅 피격 감지

## Trigger와의 비교

- Collision : 위에 올라가기, 막힘, 부딫힘 ( 막힌 곳을 **통과하지 못함** )
- Trigger : 지나가고 있거나, 지나기 시작하거나, 지난 후 ( 충돌 감지 **BUT 통과 가능**)

### Collider 연산

Sphere >> Capsule >> Box >> Mesh

- Sphere : 두 구체 중심 사이 거리만 측정
- Capsule : 원통형과 다른 오브젝트 사이의 거리 계산
- Box : OBB 연산 수행



## Raycast

- 수학적 선을 특정 방향으로 쏴 그 선에 닿는 물체가 있는지 체크
	- Physic.RayCast 메서드 사용(비관통)
	- Physic.RaycastAll ( 관통 )
	- 파라미터 -> Origin : 시작점(Position) / Direction : 방향(ex. transform.forward)
    - hit Info : 맞은 물체의 정보를 담음(RaycastHit) / MaxDistance : 레이의 길이
