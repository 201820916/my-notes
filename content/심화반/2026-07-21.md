
# 시나리오 설계 & TC 확장

- 단순한 기능 작동 여부를 넘어 유저의 실제 플레이 경험을 쫓는 추적술

## 기능 테스트(점)

- 기능 테스트 : 개별 시스템이 기획서대로 작동하는지 확인하는 기초 단계
	- 가챠 버튼을 누르면 재화가 차감되고 결과 화면에 나오는가?
	- 캐릭터가 이동 키에 맞춰 잘 움직이는가?

## 시나리오 테스트(선)

- 유저가 게임에 접속해서 종료할 때 까지의 '흐름'과 여러 기능이 복합적으로 얽히는 '상황'을 테스트.
	- "오프라인 방치 보상을 받기 위해 접속하는 순간 일일 퀘스트 초기화 시간이 겹치고 동시에 네트워크가 불안정하여 재접속이 발생한다면 보상은 정상 지급되는가?"


## 유저 페르소나에 따른 해동 패턴 예측

- 다양한 유저의 시각에서 시나리오 확장이 필요

- 하드코어/과금러 페르소나 
	- "재화가 무한대에 가까울 때 상점의 모든 패키지를 0.1초 간격으로 연속 구매하면 서버 부하나 데이터 유실이 발생하지 않는가?"

- 초보자 페르소나
	- 튜토리얼을 지시대로 따르지 않고 뒤로가기 버튼 연타 OR 앱 강제 재시작 시 튜토리얼이 꼬이지 않는가?

- 어뷰저 페르소나
	- 결제 완료가 서버로 전송되는 찰나의 순간에 비행기 모드를 켜서 통신을 차단하면 상품만 들어오고 결제는 취소되는 복사 버그가 가능한가?

##  엣지 케이스 발굴 기술

- 실게 게임 개발 프로젝트에서 빈번하게 발생하는 복합 엣지 케이스를 도출하는 훈련
- 시스템 연산과 UI, 외부 환경이 충돌하는 지점을 찾아야 한다.

- 물리 엔진 로직 맹점
	- 물리 엔진이 적용된 팽이 배틀 게임을 가정.
	- 팽이가 경기장 벽에 최대 속도로 충돌하여 물리 연산이 가장 복잡해지는 찰나의 프레임에, 플레이어가 화면을 터치해 궁극기 스킬을 발동시키면 충돌 판정과 스킬 이펙트 연산이 충돌하여 게임이 프리징(Freezing)되지 않는가?

- 조작과 UI의 간섭
	- 화면에 선을 그려서 공을 목적지로 유도하는 물리 퍼즐 게임에서, 유저가 선을 긋는 도중에 화면 상단의 **'일시정지' 팝업 UI를 동시에 멀티 터치로 누른다면?** 그려지던 선의 물리 콜라이더(Collider) 데이터는 어떻게 처리되어야 하는가?

## 완벽한 버그 리포트의 5가지 핵심 구성 요소

- 명확한 제목 : 분류 태그와 현상을 한줄로 요약
	- 예시 : \[시스템/상점] 다이아몬드 패키지 연속 구매 시, 간헐적 재화 미지급 및 클라이언트 강제 종료 현상

- 사전 조건 : 버그가 발생하기 위한 특수한 환경 세팅
	- 예시 : 유저 레벨 50 이상 / 인벤토리 슬롯 99/100 상태 / WIFI - LTE - 5G

- 재현 경로 : 가장 중요한 항목

## 심각도와 우선순위

- 런칭일은 정해져 있고, 고쳐야 할 버그는 산더미
- QA&기획자는 결함의 경중을 판단하여 개발팀의 한정된 리소스를 어디에 먼저 투입할 지 결정하는 트라이아지 역할 수행 필요

### 심각도와 우선순위 분리

- 심각도 : 결함 자체가 소프트웨어에 미치는 기술적, 치명적 파괴력(QA/개발자 관점)
	- Critical (치명) : 게임 진행 불가, 서버 다운, 결제 오류 
	- Major (주요) : 주요 기능 작동 불가 ( 우회 방법 없음 )
	- Minor (경미) : 기능은 작동하나 UI/UX 적으로 불편함

- 우선순위 : 비즈니스, 게임 내 경제(BM), 일정 관점에서 수정의 시급성.(기획/사업 관점)
	- P1 (Immediate) : 당장 핫픽스를 내거나 출시를 미뤄서라도 고쳐야 함.
	- P2 (High) : 다음 정기 업데이트 전까지 반드시 고쳐야 함.
	- P3 (Normal/Low) : 여력이 될 때 수정하거나 유저 경험에 큰 지장이 없다면 안고 갈 수 있음

### 딜레마 케이스

- 심각도와 우선순위가 비례하는가? -> NO
- 게임의 코어 재미와 BM을 이해해야만 정확한 우선순위를 매길 수 있음

- **Case A (심각도 낮음 / 우선순위 극상 - P1):**
    - **현상:** 캐릭터 가챠 시스템에서 최고 등급 캐릭터 등장 확률이 기획서(0.5%)와 달리 **5%로 적용됨**. 게임이 튕기거나 오류 메시지가 뜨지는 않음.
    - **판단:** 기술적인 에러(Crash)가 없으므로 ‘심각도’는 낮아 보일 수 있으나, 라이브 서비스에서 게임의 **핵심 BM과 경제 생태계를 붕괴시키는 초비상 상태**입니다. 최우선(P1) 수정 대상입니다.
    
- **Case B (심각도 최고 / 우선순위 낮음 - P3):**
    - **현상:** 게임 환경설정 깊숙한 곳에 있는 **‘오픈소스 라이선스 약관’ 창을 50번 연속으로 빠르게 터치하면 메모리 누수로 앱이 강제 종료(Crash)됨.**
    - **판단:** 앱이 죽어버리는 크래시 버그이므로 ‘심각도’는 매우 높습니다. 하지만 일반적인 유저가 약관 창을 50번 연타할 확률은 0에 수렴합니다. 출시를 미루면서까지 고칠 리스크는 아니며 우선순위는 낮게 배정됩니다.
    
- **Case C (심각도 하 / 우선순위 - P1):**
    - **현상:** 튜토리얼 **스킵 버튼이 우측 상단에 너무 작게 위치하여 유저들이 누르기 힘듦.**
    - **판단:** 기능적 버그는 아니지만, 초반 유저 이탈률(Retention)에 치명적인 영향을 줄 수 있습니다. 버그가 아닌 ‘개선 사항’이지만, 프로젝트의 지표를 위해 우선순위를 높여 수정안을 제안해야 합니다.
