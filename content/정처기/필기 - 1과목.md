## 애자일 방법론

소프트웨어 개발 과정에서 초기 계획에 얽매이지 않고

요구 사항 변화에 유연하고 신속하게 대응하는 것을 목표로 하는 개발방법론

### 4가지 핵심 가치

- 공정과 도구 보다는 개인과 상호작용(소통)을 우선시
- 작동하는 소프트웨어 중시
- 고객과의 협력을 중시
- 변화에 대응하는 것을 중시

### 대표적 애자일 방법론의 종류

- XP
- 스크럼 : 팀 중심의 접근법, 매일 짧은 회의와 스프린트 단위로 목표 달성 관리 기법
- 칸반 : 작업의 흐름을 시각화하여 병목현상을 줄이고 작업효율을 높이는 기법


## 요구사항 분석 및 UML


사용자가 무엇을 원하는가? -> 분석 및 표준화된 기호로 표기

### 자료 흐름도 DFD

**기본 특징 **

- **별칭**: 버블 차트(Bubble Chart), 자료 흐름 그래프라고도 불립니다.
- 
- **분석 기법**: **구조적 분석 기법**의 대표적인 도구로, 하향식(Top-down) 분할 원리를 적용하여 시스템을 세분화합니다.
    
- **한계점 (핵심 기출)**: 자료의 흐름과 처리에만 초점을 맞추기 때문에, **제어의 흐름이나 시간의 흐름(순서)은 표현할 수 없습니다**.
    

**2. 구성 요소 (상세 기호 및 영문명)**

- **프로세스 (Process)** : `원(◯)` 또는 둥근 사각형
    
    - 입력된 자료를 가공하여 새로운 자료를 출력하는 시스템의 논리적인 처리 과정을 의미합니다.
        
- **자료 흐름 (Data Flow)** : `화살표(→)`
    
    - 자료의 이동 방향을 나타내며, 화살표 위에 전달되는 자료의 이름을 표기합니다.
        
- **자료 저장소 (Data Store)** : `평행선(=)` 또는 직선(단선/이중선)
    
    - 데이터베이스, 파일, 디스크 등 시스템 내에 자료가 머무르는(저장되는) 곳을 의미합니다.
        
- **단말 / 외부 엔티티 (Terminator)** : `사각형(□)`
    
    - 시스템과 데이터를 주고받는 외부 환경(사용자, 다른 부서, 외부 시스템 등)을 의미합니다.
        

**3. DFD 작성 시 주요 원칙 및 오류

- **자료 보존의 원칙**: 프로세스가 출력 자료를 내기 위해서는 반드시 그에 맞는 입력 자료가 들어와야 합니다.
    
- **블랙홀 (Black Hole) 오류**: 프로세스에 데이터가 **입력만 되고 출력이 없는** 상태입니다. (데이터가 들어가서 사라짐)
    
- **기적 (Miracle) 오류**: 프로세스에 **입력되는 데이터가 없는데 출력만 발생하는** 상태입니다. (무에서 유가 창조됨)
    
- **단계화 (Leveling)**: 시스템 전체를 하나의 커다란 프로세스(원 1개)로 그리는 **배경도(Context Diagram, Level 0)**에서 시작하여, 시스템의 내부를 Level 1, Level 2 등으로 점점 구체화하고 세분화하여 그립니다.
    

**4. DFD와 함께 쓰이는 구조적 분석 도구**

- **자료 사전 (DD, Data Dictionary)**: DFD에 있는 자료들에 대한 구체적인 정의와 설명을 메타데이터 형태로 기록한 사전입니다.
    
- **소단위 명세서 (Mini-Spec, 처리 명세서)**: DFD의 최하위 프로세스가 어떤 로직으로 데이터를 처리하는지 구체적으로 서술한 문서입니다.

### UML : 객체 지향 모델링 표준 언어

- **구조적(정적)** 다이어그램 : **클래스, 객체, 컴포넌트, 배치, 패키지 다이어그램** 등
- **행위(동적)** 다이어그램 : **유스케이스, 순차, 상태, 활동 다이어그램** 등
- 스테레오 타입 : UML 기본 기능 외 **추가 기능** -> **<< >> 기호 사용**


## 소프트웨어 아키텍처 및 설계 원칙

- 모듈화 : 시스템의 기능을 나눈 단위, **유지보수와 재사용성**

- 결합도 : 모듈 간 상호 의존 정도
	- 낮을 수록 좋음
	- **약함 -> 강함 : 자료 < 스탬프 < 제어 < 외부 < 공통 < 내용 결합도**


- 응집도  : 모듈 내부 요소들이 서로 관련 있는 정도
	- **약함 → 강함: 우연적 < 논리적 < 시간적 < 절차적 < 교환적 < 순차적 < 기능적(Functional) 응집도.**

- 아키텍처 패턴 
	- MVC 패턴(모델-뷰-컨트롤러)
	- 마스터-슬레이브 패턴
	- 파이프-필터 패턴 등

### 소프트웨어의 상위 설계와 하위 설계

#### 상위 설계 / 구조 설계

시스템 전체의 구조와 아키텍처, 구성 요소 간의 관계를 정의합니다.

- **아키텍처 설계**: 시스템 전체의 구조 설계
    
- **데이터 설계**: 데이터베이스 및 자료의 전반적인 구조 설계
    
- **인터페이스 정의(설계)**: 시스템 구성 요소 간의 상호작용 및 데이터 흐름 정의
    
- **사용자 인터페이스 설계**: 사용자와 시스템 간의 상호작용 방식 정의

#### 하위 설계 / 상세 설계

- **모듈 설계**: 각 모듈의 내부 기능과 책임 정의
    
- **자료 구조 설계**: 모듈 내부에서 사용할 구체적인 자료 구조 설계
    
- **알고리즘 설계**: 실제 작동할 처리 절차와 로직 설계


## 객체지향 설계 원칙 ( SOLID )

5대 원칙
- **단일 책임 원칙 ( SRP )** : 객체는 단 하나의 책임만 가짐.
- **개방 폐쇄 원칙 ( OCP ):** 기존 코드를 변경하지 않고 기능 추가 가능해야 함.
- **리스코프 치환 원칙 ( LSP ):** 자식 클래스는 부모 클래스의 기능을 수행할 수 있어야 함.
- **인터페이스 분리 원칙 ( ISP ):** 사용하지 않는 인터페이스와 의존관계를 맺지 않아야 함.
- **의존 역전 원칙 ( DIP ):** 추상성이 높은 클래스와 의존 관계를 맺어야 함.

## 추상화

복잡한 문제나 시스템을 이해하기 쉽도록 **핵심적이고 공통적인 성질이나 특징만 추출하여 단순화 하는 기법**

- 과정 추상화 ( 기능 추상화 )
	- 자세한 수행 과정이나 내부 로직 상세 정의 X
	- 시스템이 수행해야 할 전반적인 기능이나 흐름만 파악

- 자료 추상화 ( 데이터 추상화 )
	- 데이터의 구체적인 표현 방식이나 저장 구조 등 세부 속성은 숨김
	- 데이터가 의미하는 대표적인 개념이나 구조로 대체하여 표현

- 제어 추상화
	- 프로그램의 제어 매커니즘 이나 이벤트 발생의 정확한 내부 절차 숨김
	- 사용자가 원하는 결과나 효과(표현) 중심으로 제어 흐름 설계

## 미들웨어

운영체제와 응용 프로그램 사이에서 클라이언트-서버간 통신과 서비스 담당

- DB : **클라이언트와 원격의 데이터베이스를 직접 연결하기 위한 미들웨어**
	- 구조 - 2-Tier 아키텍처

- RPC : 응용 프로그램의 프로시저(함수)를 사용하여 
	- **원격에 있는 프로시저를 로컬에 있는 프로시저처럼 호출하게 해줌**

- MOM : 메세지 지향 미들웨어
	- 특징 : 메시지 기반의 **비동기형 방식**으로 데이터 전달
	- 용도 : 분산 데이터 시스템 간 데이터 동기화
	- 즉각적 응답 X -> **안정적 메시지 전달 중요**할때 사용

- TP Monitor : 트랜잭션 처리 모니터
	- 특징 : **동시 접속하는 온라인 트랜잭션 처리 및 감시 미들웨어**
	- 사용자 수 증가에도 빠른 **응답속도 유지 및 부하 분산**

- ORB : 객체 요청 브로커
	- 객체 지향 시스템에서 **분산된 객체들 간의 통신을 중개하는 미들웨어**
	- 표준: 코바(CORBA, 객체 생성/배포/관리를 위한 규격) 표준 스펙을 구현

- WAS : 웹 애플리케이션 서버
	- 특징 : 사용자의 요구에 따라 데이터베이스 조회 등을 거쳐 변하는 **동적인 콘텐츠**를 처리하기 위한 미들웨어
	- 용도 : 웹 구현, JAVA 기반 엔터프라이즈 업무


## 시퀀스 다이어그램

- 시스템이나 객체들이 **어떤 순서로 메시지를 주고 받으며 상호작용 하는 지**를 시간의 흐름(**위->아래**)에 따라 시각적으로 보여주는 동적 다이어그램

### 구성 항목

- **객체 (Object) / 액터 (Actor)**: 상호작용에 참여하는 주체. **상단에 사각형으로 표시.**
    
- **생명선 (Lifeline)**: 객체가 메모리에 존재하는 기간을 표시. 
	- 객체 아래로 길게 이어진 세로 **점선으로 표현.**
    
- **실행 (Activation Box / 실행 상자)**: 객체가 메시지를 받아 **다른 객체와 상호작용하며 활성화되어 작업을 수행 중**임을 나타냄.
	- 생명선 위에 길다란 **직사각형(막대)**으로 표시됩니다.
    
- **메시지 (Message)**: 인스턴스(객체) 간에 **주고받는 데이터나 요청, 응답을 의미**합니다. 가로 방향의 **화살표**로 그려지며 동기, 비동기, 반환 메시지 등으로 구분.
