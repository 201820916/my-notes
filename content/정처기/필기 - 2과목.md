
# 개발 환경 및 빌드 도구

## 통합 개발 환경 (IDE)

- 코딩, 디버깅, 컴파일, 배포 등 개발 관련 모든 작업을 하나의 프로그램에서 처리 하는 소프트웨어 환경
	- 컴파일 : 고급 언어 작성된 프로그램 -> 컴퓨터가 실행 가능한 목적 프로그램으로 번역
	- 디버깅 : 소프트웨어나 하드웨어의 오류를 찾아 수정
- 빌드 도구 : Ant, Gradle, Maven 등이 있음.

# 자료도구

## 선형 자료 구조

- 배열, 선형리스트, 스택, 큐, 데크
	- 스택 : 한쪽 끝으로만 삽입 삭제, 후입 선출, PUSH/POP
	- 큐 : 한쪽 삽입, 다른쪽 삭제, 선입선출 구조
	- 데크 : 양쪽 끝에서 모두 삽입 삭제 가능

## 비선형 자료 구조

- 그래프 : N개의 정점일 때 최대 간선수
	- 무방향 그래프 n(n-1)/2
	- 방향그래프 n(n-1)

- 트리 : 사이클을 이루지 않도록 구성한 그래프
	- 디그리, 단말 노드 등의 용어 존재
	- 운행법 : Preorder, Inorder, Postorder


# 정렬 및 해싱

- 정렬법 : 삽입/선택/버블 외에 분할과 정복을 통해 자료 이동을 최소하는 퀵 정렬
- 해싱 : 해시 함수를 이용해 홈 주소를 계산하고 데이터를 저장 검색 하는 방식
	- 해싱 함수 종류 : 제산법, 제곱법, 폴딩법, 숫자분석법


# DB 스키마

- 외부 스키마 : 사용자나 프로그래머 입장에서의 논리적 구조
- 개념 스키마 : 조직 전체 관점에서 모든 필요 데이터를 종합한 논리적 구조
- 내부 스키마 : 물리적 저장장치 입장에서 레코드 형식 및 저장 방법을 정의한 구조


# 디지털 저작권 및 형상 관리

- DRM 구성 요소
	- 클리어링 하우스( 결제 관리 )
	- 콘텐츠 제공자

	- 식별
	- 버전 제어
	- 통제

	- 저장소 기능 : 체크아웃(받아오기), 체크인(갱신), 커밋(충돌 해결 후 갱신)


# 소프트웨어 테스트 및 클린 코드

- 테스트 관점
	- 확인(고객 요구사항 충족 여부) vs 검증(개발자 입장에서 명세서대로 만들어졌는지 점검)
	- 결함 집중(파레토 법칙) : 오류 80%는 전체 모듈 20% 내에서 발견된다.
	- 화이트 박스 테스트 : 원시 코드를 오픈하고 모든 논리적 경로 테스트
		- 기초 경로 검사, 제어 구조 검사
		
	- 블랙 박스 테스트 : 입력과 출력 검사를 확인
		- 동치 분할 검사, 경계값 분석, 원인-효과 그래프 등
		
	- 인수 테스트 : 사용자가 수행하는 테스트로 개발자 앞에서 하는 알파 테스트와 최종 사용자 환경에서 하는 베타 테스트

	- 클린 코드 작성 5원칙 : 가독성, 단순성, 의존성 배제, 중복성 최소화, 추상화

	- STAF
	- FitNesse

	- watir
